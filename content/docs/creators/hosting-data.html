Official hosting Live

When someone joins your world, Mantle starts a server for it, so you don't need to run anything.

  • Region: there's a single region at launch, and you can't choose it.
  • Capacity: players per server come from Max Players in Place settings (default 16, maximum 100).
  • Lifetime: a server closes when its last player leaves. Hosted servers run for up to 60 minutes, and hosted private servers for up to 4 hours (see What happens when you press Play). Players see "This server restarts in 5 minutes" and then "in 1 minute" before the end, and are then moved to a fresh server of your world, so save anything your scripts need to keep with DataStore.
  • Costs: there are no per-creator costs.
  • Upload limits: each account has these limits per hour:
    • 5,000 files a world is built from (meshes, materials, textures, sounds and the like)
    • 300 other files, such as avatar item files
    • 2 GiB of uploads in total
    • 600 scripts and UI documents
    • 30 new worlds
    • 120 saved drafts (512 MiB in total)
    • 60 publishes
    • 60 avatar items created or edited
    • 60 library items (vehicles, weapons and script packages) created or edited
    Past a limit, you'll see "You've uploaded too much in the last hour. Try again in N minutes." While Publish uploads files, it waits for the limit to reset and carries on by itself.

Community hosting Live

Community servers are run by players on their own machines, with a server key from Settings → Account → Hosting in Mantle. See Community-hosted servers for how it works.

  • Who can host your world: you, as the owner, always can. To let other players host it too, turn on Allow Community Servers in Place settings and publish. It's off by default. Turning it off again stops new community servers for your world, but ones already running keep going.
  • New revisions: by default, a community server moves to your latest revision once it's empty. Its host can choose to drain it first or to keep the old revision.
  • What players see: a Servers tab on the world page (see World and creator pages). Pressing Play never sends players to a community server.

Saved data (DataStore) Live

Your scripts save data with DataStore. These are the limits:

LimitValue
Value size64 KiB
Keys per subject1,024
Total per world / per player10 MiB / 1 MiB
Requests300 per minute per server
Key formatUp to 128 characters. Start with a letter or digit, then use letters, digits, ., _, : or -.
  • World and player data: DataStore:Get and DataStore:Set save data for the whole world. DataStore:GetForPlayer and DataStore:SetForPlayer save data for one player, who must be on the server. DataStore is server only.
  • Official and community data are kept apart: all official servers share the same saved data. Each community server, including one you host yourself, has its own, so it can't read or write your official servers' data.
  • Messages you may see: your script's log shows these. KEY is the name of the key you used.
    • DataStore: "KEY" was not saved -- this place is at its saved-data limit. A save went over a limit.
    • DataStore: "KEY" changed elsewhere; re-reading it (this write to it was discarded). Another server saved that key first.
    If you send too many requests, Mantle tries again for you, so you won't see a message. Ordered data stores can also report errors such as "That player is not in this server's experience."
  • Planned Tools for creators to view and reset saved data.

Secrets (API keys) Live

A secret is a named value, such as an API key or a webhook address, that you keep with your place instead of writing it in a script. You set secrets in the editor. Your server scripts read them with Secrets:Get (script API 1.47 or newer): see Secrets for how.

  • Write-only: after you save a value, no one can read it back, including you. The panel shows only a name and a masked value.
  • Server scripts only: secrets reach server scripts on Mantle-hosted servers. Players' games never get them, and neither do community servers.
  • Changes reach new servers: a server that's already running keeps the values it started with. Servers that start after your change get the new ones.

Add, replace or delete a secret Live

Before you start, sign in to Mantle in the editor and save or publish the level once. Secrets belong to the place it saves or publishes to, so a level that has never been saved or published to Mantle has none.

  1. Open the section. Choose Tools → Mantle → Place settings and find Mantle: Secrets in the Details panel. Press Refresh to load the list.
  2. Read the list. Each secret shows its name, a masked value (••••••••) and "set" with the time you last saved it. The count, such as "3 / 50", shows how many you've used. A place holds up to 50.
  3. Type a name. It's upper-cased as you type. Use capital letters, digits and underscores, starting with a letter, up to 64 characters, like WEATHER_API_KEY.
  4. Enter the value. Type it in the value box, which hides what you type. For a value with several lines, such as a private key, copy it and press Paste multi-line: the box then shows "(N characters pasted)" instead of the value. Press Clear value to start over. A value is up to 8,192 bytes (bytes, not characters), and the only control characters it can hold are tab and line breaks.
  5. Press Save secret. A new name adds a secret. A name that's already in the list replaces its value: type the name and the new value, and the old one is gone. You'll see "NAME saved. Servers that start from now on get it; running servers keep what they loaded."
  6. To delete one, type its name and press Delete the secret named above. The button is on only when the name is in the list. Mantle asks "Delete the secret NAME? Server scripts will no longer get it on servers that start from now on." Choose Yes to delete it.

Test with secrets on your PC Live

Test Locally can't read your saved secrets, because Mantle never sends them to your PC. Give it test values in a file instead. The file is only for testing. Mantle never uploads it, and publishing doesn't include it.

  1. Create the file. In the Secrets section, press Create or open secrets.local.json. Mantle makes an empty one for the open level at <Project>/MantleSecrets/<LevelName>/secrets.local.json, adds secrets.local.json to your project's .gitignore so it's never committed, and opens the file. It says "Opened PATH. It is ignored by git and used by Test Locally only."
  2. Fill it in. Write each name and its test value, like {"WEATHER_API_KEY": "abc123"}. Use \n inside a value for a line break. Save the file.
  3. Run Test Locally. It gets a copy of the file for as long as the preview runs, and deletes the copy when the preview ends. Your scripts read the values with Secrets:Get, as on a real server.

Your creator page Live

Your creator page shows your picture (or your initial), your name, "N worlds" ("1 world" for one, plus "· M playing now" while anyone is playing) and a grid of your worlds titled "Worlds". If you haven't published anything, it shows "Nothing published yet." Other players see Report and Block in a "…" menu there.

  • Your name comes from the account you sign in with (up to 32 characters). Profiles don't have a bio. The only thing you can change is your picture, and it has to pass review.
  • Planned Creator verification and following.

Content rules

  • Live Mantle screens uploaded textures, scripts and UI documents automatically. It doesn't screen meshes and sounds automatically: player reports cover them. Rejected content stops you publishing, and moderators can approve or reject assets and scripts.
  • Live Place files can be up to 8 MiB and must have a name. Meshes, materials and textures from your project are uploaded with your world. See Your own assets.
  • Live Moderators can remove an uploaded file from your account. After that it can't be uploaded or used again ("A moderator removed this asset from your account, so it cannot be uploaded or used again."), so replace it to publish.
  • Planned Moderator takedowns of worlds. For now, a world's owner can remove it.
  • Planned Screening for community server names.
