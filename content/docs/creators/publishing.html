How publishing works Live

Two commands in Tools → Mantle put your level on Mantle: Save to Mantle ("Upload this level as a private draft. Nobody else can see it.") and Publish. Both ask you to sign in first if you haven't. Publish also shows the picture your world will have in the catalogue (see the Thumbnail row in Place settings) and asks "What changed in this version?" for optional revision notes, which are kept with the revision. Notes over 1,000 characters are cut to 1,000 when they are sent, and notes over 2,000 characters are refused.

Both run in the background, so you can keep working. The Mantle Publish tab shows each step, with a progress bar, a "Needs your attention" list and a Details log:

  1. Check this place

    Runs the same checks as "Check this place". If anything fails, you'll see "This place has N problem(s) to fix first."

  2. Prepare meshes and materials

    Converts the meshes and materials from your project that the level uses. A level built only from library assets skips this.

  3. Upload to Mantle

    Uploads the converted files, your Script Assets, the images in the level's UI folder (see UI documents) and the world's thumbnail. Files you've uploaded before aren't sent again. If the thumbnail can't be taken, the publish carries on without it and the tab warns "The place's thumbnail could not be taken (…), so it publishes without a picture." The world then has no picture. Publish again, or choose another view in Place settings.

  4. Mantle processes and screens them

    Mantle processes the uploaded files and screens the textures (including UI images). Something that needs a moderator shows as "waiting for a Mantle moderator to look at it." Save to Mantle skips this step.

  5. Publish

    Mantle uploads every script in the level's Scripts folder and its Packages folder (see Script packages), and the documents and stylesheets in its UI folder, and screens them. The first time you publish a level, this creates a new world with the level's name. Later publishes update that same world, as long as the level is still linked to it (see Which world a publish goes to). Mantle saves your draft and, for Publish, makes it live as a new, numbered revision. If the place has vehicles, weapons or script packages of your own, the tab first asks "Vehicles, weapons and script packages in this place: who can use them": Public: listed in the library for every creator (tick "I own this content or its licence permits public redistribution on Mantle" to go live) or Private: only you can use them.

When it works, you'll see "Saved to Mantle. Nobody can see it until you publish." or "Published revision N. Anyone can join it now." If it stops, the tab says why and what to do. Cancel stops at any point without publishing anything, and Publish again carries on from where it stopped: everything already uploaded stays on Mantle.

Which world a publish goes to Live

The editor remembers which world each level publishes to, so a later publish updates it instead of making a copy. The link is kept in your own editor settings for the project, not in the files you check in, and it's saved per Mantle account and per level path. So Publish makes a new world when:

  • you publish from another PC, because the link isn't there.
  • a teammate publishes the level from their account, because the link is yours only.
  • you rename or move the level, because its path changed.
  • you open a fresh checkout of the project, because the link isn't in the files you check in.
  • you deleted the world. The publish stops first and tells you (see What stops a publish), and the next one creates a new world.

You can see the saved links under Editor Preferences → Plugins → Mantle.

Script packages Live

When a place goes live, each script package in the level's Packages/ folder is published as a library item, public or private, in the same step that asks about vehicles and weapons, and the place stores it under the folder's name. A later publish adds a new version only when a package's files or package.json changed. Save to Mantle doesn't publish packages, so a draft leaves out the Script Points of packages that aren't stored yet. See Publishing a package.

Using an AI agent Live

The Mantle plugin includes tools that Unreal's own Model Context Protocol (MCP) server can offer to an AI agent, such as Claude Code, so you can ask it to check or publish your place. It uses Epic's experimental Unreal MCP plugin, which needs Epic's experimental Toolset Registry plugin. Both are off by default. Mantle doesn't turn them on for you, the Mantle tools only appear once Toolset Registry is on, and without them the Mantle plugin works exactly as before.

  1. Turn on the plugins

    In Edit → Plugins, enable Unreal MCP, which turns on Toolset Registry with it, then restart the editor.

  2. Start the server

    Run the console command ModelContextProtocol.StartServer, or turn on Auto Start Server under Editor Preferences → General → Model Context Protocol. By default it listens on http://127.0.0.1:8000/mcp.

  3. Connect your agent

    Point your agent at that address, for example claude mcp add --transport http unreal-mcp http://127.0.0.1:8000/mcp.

  4. Sign in yourself

    To publish or list your places, sign in in the editor first. The agent never sees your creator token, and no tool asks for one. If an agent asks you to paste your token into its chat, don't.

Revisions

  • Live Every publish creates a new revision, numbered in order. Until you publish, each save replaces your draft.
  • Live Running games keep going. Publishing doesn't disrupt players mid-game: games already running stay on the revision they started with. New games start on your latest revision.
  • In progress Previews and staged rollouts: try a new revision privately, then release it to a percentage of players before everyone else. Controls are coming to the editor.
  • In progress Rollback: go back to an earlier revision. Controls are coming to the editor. A revision that stops being live can be made live again for 180 days. A preview or staged revision that never went live can be for 30 days. After that you'll see "That revision is past its retention window and can no longer be made live."

Managing your worlds Live

Live In the Mantle game, outside a world, open Settings → Account and choose Manage places (under "My Places") to open My Places: your published worlds and drafts, the most recently updated first. Each one shows its name, "Published" or "Draft", when it was last updated (in UTC), its description and its place ID. Names and descriptions come from your latest draft.

  • View place opens the world's page. It's only available for a published world.
  • Copy ID copies the place ID to your clipboard.
  • Delete asks first: "Delete this place? It will disappear from discovery and your places. All active servers will close and players will be disconnected. You cannot undo this here." Choose Delete place to go ahead, or Cancel. You'll see "Place deleted."
  • Refresh reloads the list, and Load more shows older places.
  • To change a world, edit the level and save or publish again from the editor. Planned Editing a world's details in the editor or on My Places.
  • Deleting a world removes it from the catalogue, featured list, charts and favourites, and closes its servers. You can't undo this. Deleted worlds are removed for good after 180 days.
  • Each world has one owner. Planned Transferring ownership, plus collaborators and teams.

How worlds get discovered Live

  • Catalogue and search: published worlds are listed newest first. Search covers world names, descriptions and creator names, and results can be sorted by Best match (the default), Most played or Newest. Your creator page lists all your worlds.
  • Featured: up to 12 worlds hand-picked by Mantle.
  • Charts: "Top 10 this week" shows the most played worlds of the past week. "New and rising" shows worlds that are picking up players, then the newest worlds.
  • Stats: your profile shows how many worlds you've published. World cards show how many people are playing now. Charts show unique players and play time. Planned Detailed stats for your own worlds.
