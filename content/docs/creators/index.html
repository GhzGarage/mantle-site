What you need

  • Live Unreal Engine 5.8 from the Epic Games Launcher.
  • Live Windows (64-bit). You only need Visual Studio if your project has its own C++ code.
  • Live The Mantle plugin is free on Fab for Unreal Engine 5.8 on Windows (version 0.1.0, beta). Get it from Mantle Core on Fab. See The Mantle Core plugin for installing it and what else it needs.

Signing in to publish Live

The editor signs in with a creator token that you make in the Mantle game.

  1. Make a token

    In Mantle, open Settings → Account → Creator tokens. Give the token a name (up to 48 characters, such as "My laptop"), pick when it expires (Never, 30 days, 90 days or 1 year) and choose Create. The token is shown once, so copy it right away. An account can have up to 10 tokens at a time: revoked and expired tokens don't count.

  2. Paste it into the editor

    Choose Tools → Mantle → Sign in with creator token... and paste it. If you skip this, Save to Mantle, Publish, the Cosmetics panel and the Library panel ask for a token when you use them.

  • The editor keeps the token in memory until it closes. It's never saved to disk, so you'll paste it again after a restart.
  • To sign in without pasting, for example on a build machine, set the MANTLE_AUTH_TOKEN environment variable to a creator token before you start the editor. The menu then shows "Signed in with MANTLE_AUTH_TOKEN" (or "Signed in as [your name] (MANTLE_AUTH_TOKEN)") and has no Sign out command. To use a different token, change the variable and restart the editor.
  • Once you're in, the Mantle menu shows "Signed in as [your name]" and a Sign out command.
  • Revoking a token in Settings stops it at once. If a token is revoked or expires, the editor signs you out and asks for a new one the next time you save or publish.
  • If a pasted token isn't right, you'll see why, for example "That isn't a creator token: they start with mct1. Create one in the Mantle game under Settings > Account > Creator tokens."

Checking from the console: Mantle.Check Live

Mantle.Check runs Publish's check and export on the open level, without publishing and without contacting Mantle. Use it on a big level or from a script, where the Check this place window is awkward. Open the level, then type the command in the editor's console (the Cmd box in the Output Log). The editor can also run it for you at start-up with -ExecCmds.

ArgumentWhat it does
Mantle.CheckChecks the level and logs one line per finding.
-Export=<folder>Writes place.json (the place file Publish would upload) and check.txt (the findings) to that folder. If the check finds errors there is no place file: it logs "MANTLE_CHECK_EXPORT none: the check found errors, so there is no place file to write."
-Thin=autoWhen the place is over the instance or file-size limit, thins foliage and instances evenly so it fits. Nothing is thinned otherwise, and -Thin=off (the default) never thins.
  • Unlike Check this place, it loads every World Partition cell and every Level Instance the editor hasn't loaded, as Publish does, and lets them go when it ends. See What "Check this place" catches.
  • Each finding is one log line starting MANTLE_CHECK_ERROR or MANTLE_CHECK_WARNING. Findings aren't capped at 12. The run starts with MANTLE_CHECK_START level=… thin=… and ends with one line you can search for:
    MANTLE_CHECK_DONE ready=1 errors=0 warnings=0 placeBytes=… instances=… grouped=… thinned=… drawDistances=…
  • ready is 1 when there are no errors. placeBytes is the size of the place file, which can be at most 8 MiB. instances is how many instanced meshes it holds, at most 100,000. grouped is how many identical mesh actors were turned into instance sets, and thinned is how many instances thinning removed. drawDistances is how many meshes and instance sets were given a draw distance.
  • If the place is over a limit and thinning would fix it, the log also says what thinning would remove: "MANTLE_CHECK_THIN_OFFER … Run Mantle.Check -Thin=auto, or Mantle.Publish -Thin=auto, to use it."
  • It also logs what the export kept, changed and left out, one MANTLE_COVERAGE line for each kind of content.
  • It doesn't convert meshes and materials, because that happens while Publish uploads them. Findings that only show then aren't in its report, for example when Publish repairs bad LOD screen sizes: "Mesh '…': its LOD screen sizes (…) were not each below the one before, so they were published as (…)." Your mesh isn't changed.

-Export wants a folder to write the place file to, as in -Export=D:/Checks/MyLevel.Give -Export= a folder.
-Thin wants auto (thin foliage and instances evenly if the place is too big) or off, not '…'.Use -Thin=auto or -Thin=off.

How Mantle fits a big place Live

These happen when Publish or Mantle.Check writes the place file. Neither changes your level.

  • Grouping. Four or more identical static mesh actors become one instance set. They must share a mesh, materials, collision, shadow setting and surface, and be static, with no parent, no tags, no physics and no interaction. Each keeps its place, rotation and scale, but they are no longer separate named objects. The log says how many were grouped.
  • Thinning. Only if you choose it (see "Too many instanced meshes" above). It removes instances evenly across the level, foliage first and then props and PCG output, and says how many went and what the file size becomes.
  • Draw distance. A mesh or instance set stops drawing past a distance. Mantle uses the one you set on the mesh (Desired Max Draw Distance, or an instanced component's end cull distance) and skips meshes set to Never Distance Cull. With none set, it picks one by the mesh's size, from the radius of its bounding sphere at the scale you placed it: under 30 cm, 6,000 cm; 30 to 100 cm, 12,000 cm; 100 to 300 cm, 25,000 cm; 300 to 1,000 cm, 60,000 cm. A mesh with a radius of 1,000 cm or more is always drawn, and so is one whose own distance is over 1,000,000 cm. A Mantle client that is too old to read draw distances gets none, and the export reports "draw distances … left out, so meshes are drawn from any distance: needs a newer Mantle client".

Things that aren't published
  • BSP brushes, engine volumes (Trigger Volume, Blocking Volume and so on), placed pawns and cameras are left out of the published world. Use static meshes instead, and use Trigger Box or Trigger Sphere actors for trigger areas.
  • Text Render Actors are published as world text.
  • UI documents, stylesheets and images in the level's UI/ folder publish with the place. See UI documents.
  • Ambient Sounds publish with your own sound waves. Mantle has no built-in sounds.
  • Actors set to Movable stay dynamic in the published world.
  • Actor tags are kept, so your scripts can find things by tag.

Testing a world
