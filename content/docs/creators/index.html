Signing in to publish Live

The editor signs in with a creator token that you make in the Mantle game.

  1. Make a token

    In Mantle, open Settings → Account → Creator tokens. Give the token a name (up to 48 characters, such as "My laptop"), pick when it expires (Never, 30 days, 90 days or 1 year) and choose Create. The token is shown once, so copy it straight away. An account can have up to 10 tokens.

  2. Paste it into the editor

    Choose Tools → Mantle → Sign in with creator token... and paste it. If you skip this, Save to Mantle, Publish and the Cosmetics panel ask for a token when you use them.

  • The editor keeps the token in memory until it closes. It's never saved to disk, so you'll paste it again after a restart.
  • Once you're in, the Mantle menu shows "Signed in as [your name]" and a Sign out command.
  • Revoking a token in Settings stops it at once. If a token is revoked or expires, the editor signs you out and asks for a new one the next time you save or publish.
  • If a pasted token isn't right, you'll see why, for example "That isn't a creator token: they start with mct1. Create one in the Mantle game under Settings > Account > Creator tokens."

You'll find the Mantle server address in Project Settings → Plugins → Mantle → Connection → Api Base Url.

Things that aren't published
  • BSP brushes, engine volumes (Trigger Volume, Blocking Volume and so on), placed pawns, landscape and foliage are left out of the published world. Use static meshes instead, and use Trigger Box or Trigger Sphere actors for trigger areas.
  • Ambient Sound actors can't be used yet: Mantle has no built-in sounds, and you can't upload your own yet.
  • Actors set to Movable stay dynamic in the published world.
  • Actor tags are kept, so your scripts can find things by tag.

Testing a world

  • Play in Editor (PIE) doesn't run Mantle worlds or scripts. To check your build, use "Check what players receive". To test gameplay, publish your world and join it with the Mantle client.
