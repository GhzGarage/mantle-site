Live You can build a world from static meshes, materials and textures in your own project, whether you made them yourself or they came from a Fab pack. You never upload them by hand: when you publish, the plugin finds every mesh and material the level uses that isn't in Mantle's built-in library, prepares it for Mantle and uploads anything new.

Before you start

  • You need the Mantle plugin and to be signed in with a creator token.
  • Static Mesh Actors and Blueprint prefabs publish today. Skeletal meshes, landscape, foliage and your own vehicles are in the plugin but wait for the next game release. See What you can place.
  • Sound waves from your project publish too. See Sounds.

Getting your assets into a world

  1. Bring the assets into your project

    Add the Fab pack to your project, or import your own meshes and textures, as you normally would in Unreal. Nothing about them needs to change for Mantle.

  2. Place them in the level

    Drag each Static Mesh into the level so it becomes a Static Mesh Actor. If a pack gives you Blueprint prefabs, place them as they are: their meshes, lights and collision publish as parts (see Blueprint prefabs). You can change materials on the actor's slots as usual; a slot with no material uses Unreal's default material.

  3. Set collision and shadows on the actor

    The actor's Collision Enabled decides how players meet it: No Collision publishes as none, Query Only as overlap, and anything else as blocking. Cast Shadow is kept too.

  4. Save your assets

    Save the level and any meshes or materials you changed. Unsaved assets still publish, but they're prepared again on every publish, which is slower. See The conversion cache.

  5. Run Check this place

    Choose Tools → Mantle → Check this place. It checks every mesh and material from your project once, however many actors use it. Errors must be fixed before you can publish. Warnings tell you what will look different in Mantle, but don't stop anything. See Messages and how to fix them.

  6. Publish

    Choose Tools → Mantle → Publish (or Save to Mantle for a private draft). The Mantle Publish tab opens and shows each step. You can keep working while it runs.

What players see

Meshes

  • Levels of detail: the mesh's own LOD1 and LOD2 are published with the screen sizes set in the editor, so players far away see the lighter versions. A LOD with more triangles than the one before it, or past the limits above, is left off with a warning: "Mesh '…': LOD N was left off because …; players see the LODs before it at every distance." UV channel 1 and painted vertex colours are published too. Game versions before the next release show LOD0 at every distance.
  • Nanite: players see a Nanite mesh's fallback mesh. If it looks too coarse, raise Fallback Triangle Percent in the mesh's Nanite settings. If it's over the triangle limit, lower it.
  • Collision: a mesh's simple collision (boxes, spheres, capsules and convex hulls) is published, unless its Collision Complexity is Use Complex As Simple. A mesh without simple collision, or with more than the limits above, collides using its own triangles. Tapered capsules and level sets are left out, with a warning. Game versions before the next release always collide using the triangles.

Materials

When you publish, Mantle converts each material to work in the game. This works for any material, including material instances and graphs built from material functions.

  • Kept: base colour, normal, roughness, metallic, ambient occlusion and emissive (with its strength, up to 100).
  • Blend modes: Opaque, Masked (with its opacity mask clip value) and Translucent. Other blend modes become ordinary translucency.
  • Two Sided is kept.
  • Unlit materials become a glowing material that lighting still touches.
  • Next release Per-texture tiling, offset and rotation, normal and occlusion strength, ambient occlusion on UV channel 1, and vertex colour multiplying the base colour.
  • Next release Car paint: an opaque, one-sided Clear Coat material publishes as Mantle's car paint, a clear coat over its base colour, with optional metallic flakes (give it FlakeDensity, FlakeSize or FlakeTint parameters). "Check this place" notes it: "it is a Clear Coat material, so it publishes as Mantle's car-paint shading".
  • Next release Scrolling textures: a Panner feeding a Texture Sample's UVs, that sample going straight into Base Color, Normal or Emissive (or the ORM group), keeps scrolling in game at the same speed and tiling, instead of freezing. A panned base colour on a masked or translucent material needs its opacity to be the same sample's alpha.
  • Next release Swaying grass and foliage: a SimpleGrassWind node on World Position Offset, with constant Wind Intensity and Wind Speed and a Wind Weight of Vertex Color's red, 1 - V of the first UV, or a constant 1, sways in game instead of standing still. It stops swaying past 50 m, and doesn't work on translucent materials.
  • Next release World-aligned textures: a WorldAlignedTexture (or WorldAlignedNormal) node on Base Color, Normal or the ORM group, with one constant tile size and sharpness and no World Position input, samples by world position in game instead of the mesh's own UVs, so its pattern runs on unbroken across neighbouring meshes. Opaque materials only; emissive keeps using UVs.
  • Next release Vertex-painted layer blends: a Lerp between two plain Texture Samples by one Vertex Color channel, on Base Color (with Normal and the ORM group blending the same way, or staying a plain sample), keeps the painted layer in game instead of dropping it. Opaque materials only.

These five recognised shapes are the only ones Mantle carries: anything built differently, even if it looks similar in the material editor, still falls back to the plain conversion below. They aren't kept on car paint, or (other than swaying and a panned emissive) on unlit materials.

Some materials wait for the next release

A material that uses any of the settings marked Next release above can't be uploaded until the game release that reads them is out. The Mantle Publish tab shows "Mantle could not process '…': /[setting] is not read by the released game yet; upload this material once a Mantle release reads [setting], or remove it for now." Until then, use a material without that setting on those meshes, for example with the same tiling on every texture.

Some effects can't be kept. Check this place names each one as a warning, and the material still publishes. The four rows marked below are exceptions once Next release arrives: built in exactly one of the recognised shapes above, they carry across instead; anything else built the same way in spirit (a Panner feeding something other than a plain Texture Sample, wind on a translucent material, and so on) still falls back to the row's behaviour.

Textures

  • Textures are at most 2048 on the longest side. Larger ones are scaled down when you publish, keeping their shape. Detail finer than that is lost.
  • Each texture file must fit in 8 MB. If one is too big, it's compressed harder or scaled down, with a warning.
  • Every texture is screened before a place can go live with it.
  • If one image is used for two different jobs, such as colour in one material and a normal map in another, one of them may be left out. See the upload messages.

The conversion cache

The plugin keeps what it has prepared in your project's Saved/Mantle/AssetCache folder, so a later publish only prepares what changed.

  • Only saved assets are kept. An asset with unsaved changes is prepared every time until you save it.
  • A plugin update or a different engine version may convert everything again once.
  • It's safe to delete the folder. Everything is simply converted again on the next publish.

Updating or replacing an asset

  • To change an asset, edit it in Unreal, save it and publish again. Only what changed is uploaded.
  • To replace an asset, swap it in the level (or on the actor's material slot) and publish again. The new one is uploaded like any other.
  • Servers already running keep the revision they started with, so players in them see the old version until the server empties. See Revisions.
  • If you edit the level while a publish is running, the plugin prepares and uploads what's new before saving. If the level keeps changing, it stops with "The level kept changing while it was being published. Pause editing for a moment and choose Publish again; nothing is uploaded twice."

If a file is rejected or removed

  • Rejected in screening or review: the place can't go live with it. Replace the texture (or the material or mesh that uses it), or remove what uses it, then publish again.
  • Waiting for a moderator: nothing goes live until it's approved. Choose Publish again once it is. Nothing is uploaded twice.
  • Removed by a moderator: moderators can remove a file from your account, usually after a licence complaint (for example a Fab pack you don't have the rights to). After that it can't be uploaded or used again, and your world's next publish is stopped until you replace it or remove what uses it.
Only use assets you have the rights to

Everything you upload is tied to your account. Use your own work, or Fab and marketplace content whose licence lets you use it in your game.

Crediting assets Live

If an asset's licence asks for credit, such as Creative Commons BY, add it in Project Settings → Plugins → Mantle Credits. Each rule names a content folder, such as /Game/Fab/Crates, and the Attribution players are shown for everything under it: plain text, one line, at most 500 characters, for example the title, author, source and licence. The deepest matching folder wins. One asset can override its folder with the MantleAttribution metadata tag on its package (an empty tag means no credit). Credits show on the world page of every place that uses the asset. Nothing is credited unless a rule or tag says so. The rules are saved with the project, so everyone working on it shares them.

Upload limits

Each account can upload up to 5,000 files (meshes, materials, textures, sounds and the rest) and 2 GiB per hour. Files your account already has on Mantle aren't sent again, so they don't count. A big pack's first publish can reach the limit. When it does, Publish pauses by itself and shows "Mantle's hourly upload limit is reached. Uploading continues by itself at HH:MM (in about N minutes); you can keep working meanwhile." If the wait would be longer than about an hour, it stops instead and tells you when to try again. Everything uploaded so far is kept. See Official hosting for the other limits.
