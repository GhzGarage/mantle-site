Copy-ready recipes

Each code block is one file, and the label above it shows where the file goes. The main recipes fit together into one place written in Luau, JavaScript and TypeScript. If a recipe imports the shared configuration module, copy that module too. The language switch only changes the standalone versions, which come in every language.

Each recipe finds the actors in your level by a tag that starts with guide_code_. Give your actors matching tags, or change the tags in the code. The visual scripting examples use their own tags so both can live in one place.

Shared configuration module

This module holds the settings the other recipes share. Copy it into the same nested folders, keeping the exact capitalisation of every folder and file name. By default, coins respawn after five seconds and a round lasts 60 seconds. Anything in a Modules folder is only ever used as a module, never run as a script by itself.

Scripts/Shared/Modules/Config/GuideConfig.luau
-- Shared configuration is module-only, including nested Modules directories.
return {
	SafeSpawn = Vector3.new(0, 0, 120),
	CoinRespawnSeconds = 5,
	RoundSeconds = 60,
}

A kill brick that returns the player to safety

This builds a hazard that sends players back to safety when they touch it: tag the hazard actor in your level guide_code_killbrick. The script teleports the player to their saved checkpoint, or to the configured safe spawn if they haven't reached a checkpoint yet.

Scripts/Server/GuideKillBricks.luau
local Config = require("Shared/Modules/Config/GuideConfig")
World:OnTagged("guide_code_killbrick", function(brick)
	brick.Touched:Connect(function(player)
		local spawn = State:Get(`guide.respawn:{player.UserId}`) or Config.SafeSpawn
		player:Teleport(spawn)
	end)
end)

Coins that bob, score and respawn

This builds coins that bob up and down and give a point when collected: tag each coin actor in your level guide_code_coin. The server bobs the coin 40 cm up and down with a tween. When a player touches it, the server hides it, awards one point and shows it again after five seconds. Checking Visible first stops two touches at the same moment from scoring the same pickup twice. Keep these long-lived coins separate from templates you clone and throw away. The tween uses Sine easing with InOut, so the coin slows down gently at the top and bottom of each bob.

Scripts/Server/Modules/Recipes/ScoreRules.luau
local Rules = {}
function Rules.key(player)
	return `guide.score:{player.UserId}`
end
function Rules.award(player)
	local key = Rules.key(player)
	local value = (State:Get(key) or 0) + 1
	State:Set(key, value)
	return value
end
return Rules
Scripts/Server/GuideCoins.luau
local Config = require("Shared/Modules/Config/GuideConfig")
local Score = require("./Modules/Recipes/ScoreRules")
World:OnTagged("guide_code_coin", function(coin)
	local home = coin.Position
	task.spawn(function()
		while true do
			coin:Tween({ Position = home + Vector3.new(0, 0, 40) }, 1, "Sine", "InOut"):Wait()
			coin:Tween({ Position = home }, 1, "Sine", "InOut"):Wait()
		end
	end)
	coin.Touched:Connect(function(player)
		if not coin.Visible then return end
		coin.Visible = false
		Score.award(player)
		task.wait(Config.CoinRespawnSeconds)
		coin.Visible = true
	end)
end)

Scripts/Server/Coins.py
def setup(coin):
    home = coin.position

    def bob():
        while True:
            yield coin.tween({"position": home + Vector3(0, 0, 40)}, 1, "Sine", "InOut").wait()
            yield coin.tween({"position": home}, 1, "Sine", "InOut").wait()
    task.spawn(bob)

    def on_touch(player):
        if not coin.visible:
            return
        coin.visible = False
        key = f"score:{player.user_id}"
        State.set(key, (State.get(key) or 0) + 1)
        yield task.wait(5)
        coin.visible = True
    coin.touched.connect(on_touch)

World.on_tagged("guide_code_coin", setup)

A door that opens when someone walks up

This builds a door that slides open when a player comes close: tag the door actor in your level guide_code_door. Every 0.2 seconds, the script checks whether any player is within 450 cm of the door's saved closed position. If so, the door tweens 390 cm downward over 0.6 seconds. It closes again once everyone has left. The trigger area stays at the door's original position and doesn't move with the door.

Scripts/Server/GuideDoor.luau
local door = World:FindByTag("guide_code_door")[1]
local closed = door.Position
local isOpen = false
while true do
	local near = false
	for _, player in Players:GetPlayers() do
		if player.Position and (player.Position - closed).Magnitude < 450 then
			near = true
		end
	end
	if near ~= isOpen then
		isOpen = near
		State:Set("guide.door.open", isOpen)
		door:Tween({ Position = if isOpen then closed - Vector3.new(0, 0, 390) else closed }, 0.6)
	end
	task.wait(0.2)
end

Round timer on every client HUD

This builds a round timer that shows the current round and time left on every player's screen. You don't need to tag anything in the level: just add both scripts. The server keeps track of the round and the time left. The JavaScript client creates its UI nodes first and then observes State, so players who join late still get the current values. The round-start announcement is a toast: it shows at the top centre of each player’s screen for three seconds, then goes away.

Scripts/Server/GuideRounds.luau
local Config = require("Shared/Modules/Config/GuideConfig")
local announce = Net:Remote("GuideAnnounce")
local round = 0
while true do
	round += 1
	State:Set("guide.round", round)
	announce:FireAllClients(`Round {round} started`)
	for remaining = Config.RoundSeconds, 0, -1 do
		State:Set("guide.timeLeft", remaining)
		if remaining > 0 then task.wait(1) end
	end
end
Scripts/Client/GuideHud.js
// Create retained widgets before subscribing. Observe replays current State for late joiners.
const frame = UI.create("frame");
const roundLabel = UI.create("text");
const timeLabel = UI.create("text");
roundLabel.setParent(frame);
timeLabel.setParent(frame);
roundLabel.setSemantics("label", "Current round", "The current round number", 0);
timeLabel.setSemantics("label", "Time remaining", "Seconds left in this round", 0);
State.observe("guide.round", (round) => {
	roundLabel.setText(`Round ${round ?? 0}`);
});
State.observe("guide.timeLeft", (seconds) => {
	timeLabel.setText(`Time left: ${seconds ?? 0}s`);
});
Net.remote("GuideAnnounce").onClientEvent.connect((message) => UI.toast(message, 3));

A button players ask the server to press

This builds a button that squashes down and springs back when a player presses it: tag the button actor in your level guide_code_button. When the local player touches the button, the client asks the server to press it. The server checks the message and where the sending player really is, and turns away new presses while the button is still busy. It plays both scale tweens, then tells the player the press worked. The client's message never picks which player pressed, and never adds a press by itself.

Scripts/Client/GuideButtonPrompt.luau
local button = World:FindByTag("guide_code_button")[1]
button.Touched:Connect(function(player)
	if player == Players.LocalPlayer then
		Net:Remote("GuidePressButton"):FireServer("press")
	end
end)
Scripts/Server/GuideButton.luau
local button = World:FindByTag("guide_code_button")[1]
local busy = false
local result = Net:Remote("GuideButtonResult")
Net:Remote("GuidePressButton").OnServerEvent:Connect(function(player, message)
	if message ~= "press" then
		result:FireClient(player, "payload")
		return
	end
	if not player.Position or (player.Position - button.Position).Magnitude > 400 then
		result:FireClient(player, "distance")
		return
	end
	if busy then
		result:FireClient(player, "busy")
		return
	end
	busy = true
	local size = button.Scale
	button:Tween({ Scale = Vector3.new(size.X, size.Y, size.Z * 0.3) }, 0.15):Wait()
	button:Tween({ Scale = size }, 0.4, "Back", "Out"):Wait()
	State:Set("guide.button.presses", (State:Get("guide.button.presses") or 0) + 1)
	busy = false
	result:FireClient(player, "pressed")
end)
State:Set("guide.button.presses", 0)

Cloning and destroying things

This shows how to copy and remove objects from a script: place a separate template actor tagged guide_code_template, and another actor tagged guide_code_retired. The script hides the template and makes one visible clone that stays. It then makes a second clone and destroys it, and destroys the retired actor you placed in the level. Players who join later see the clone that stayed and none of the destroyed objects. Clones copy their template's tags, so don't put pickup tags on a template unless you want every clone to be picked up by that recipe too.

Scripts/Server/GuideClones.luau
local template = World:FindByTag("guide_code_template")[1]
template.Visible = false
local survivor = template:Clone()
survivor.Position = Vector3.new(4500, 2000, 120)
survivor.Visible = true
survivor:AddTag("guide_code_survivor")
local doomed = template:Clone()
doomed:AddTag("guide_code_destroyed")
doomed:Destroy()
local retired = World:FindByTag("guide_code_retired")[1]
retired:Destroy()

TypeScript checkpoints and Luau respawns

This builds checkpoints in TypeScript that work with the Luau kill brick: tag each checkpoint pad in your level guide_code_checkpoint. The TypeScript script imports its nested Rules module. When a player touches a pad, it saves a respawn position (a Vector3) in State. GuideKillBricks.luau, shown above, reads that position the next time the player touches a hazard. Don't add a second kill brick handler.

Scripts/Server/Modules/Rules/CheckpointRules.ts
export function key(userId: string): string {
	return `guide.respawn:${userId}`;
}
export function destination(pad: Entity): Vector3 {
	return pad.position.add(new Vector3(0, 0, 120));
}
Scripts/Server/GuideCheckpoint.ts
import { key, destination } from "./Modules/Rules/CheckpointRules";
World.onTagged("guide_code_checkpoint", (pad: Entity) => {
	pad.touched.connect((player: Player) => {
		State.set(key(player.userId), destination(pad));
	});
});

Saving data across sessions

Use DataStore Server to save boolean, number or string values so they’re still there in later sessions (tables too, from API 1.13: see saved tables). You can save them for the whole place (Get/Set) or for each player (GetForPlayer/SetForPlayer). There’s nothing to set up in the level.

A missing value doesn’t mean zero

When DataStore:GetForPlayer returns nil, you can’t tell whether this is the player’s first visit, their data hasn’t finished loading, or the load failed. Scripts can’t yet get a signal when data has loaded, or confirmation that a write was saved. Don’t turn nil into zero and write it back, or you could overwrite a larger saved value such as a best score.

Saved tables, removing and listing keys

From API 1.13, DataStore:Set and SetForPlayer also take a table of booleans, numbers, strings and tables, nested up to 4 levels deep and at most 64 KiB, so one key can hold a player's whole profile. Lists come back as lists and objects as objects, but an object's key order isn't kept. Vector3, entities and functions can't be saved. RemoveKey deletes a key, and ListKeys pages through keys that start with a prefix, 100 at a time. Like Get, ListKeys can lag behind other servers: it may not see what another server of the place wrote a moment ago.

Scripts/Server/GuideProfile.luau
Players:OnPlayer(function(player)
	DataStore:SetForPlayer(player, "guide.profile", { coins = 120, owned = { "sword", "shield" } })
end)

DataStore:RemoveKey("guide.event.spring")   -- Get reads nil at once; deleted in the background

local cursor = nil
repeat
	local page = DataStore:ListKeys("guide.", cursor)   -- up to 100 keys, in key order
	for _, key in page.keys do
		print(key)
	end
	cursor = page.nextCursor
until cursor == nil

A leaderboard across every server

The easy way (API 1.26). Fill an ordered store keyed by player.UserId, then show it with the built-in panel players open with Tab:

Scripts/Server/GuideWins.luau
local wins = DataStore:GetOrderedDataStore("wins")
Leaderboard:Configure("wins", { title = "Most wins", valueLabel = "Wins" })

local function onRoundWon(player)
	wins:IncrementAsync(player.UserId, 1)
end

Use ascending = true in the options table for "lowest is best" (race times), and Leaderboard:Clear() to hide the panel. Keys that aren't a UserId show as written (team names). Server scripts only.

Your own leaderboard UI. This keeps a wins leaderboard for your place and shows the top 10 on every player's screen with your own widgets, for when you want more than the built-in panel. It needs API 1.13. An ordered store keeps one whole number per key and reads them back sorted, across every server of the place. Key it by player.UserId exactly, so each player has one row: that's also how Mantle removes a player's rows when they delete their account, and includes them in their data export. Every ordered-store call returns a Signal that fires once with a result table: ok, error when it failed, and the answer (value, or entries and nextCursor for a page). Call :Wait() on it straight away, or connect with :Once. IncrementAsync adds in a single step, so two servers adding a win at the same moment never lose one.

Fire the GuideRoundWon event with the winning player from whichever script decides a round, for example Events:Get("GuideRoundWon"):Fire(player). The store only holds ids, so the server fills in names for players who are in this session.

Scripts/Server/GuideLeaderboard.luau
local wins = DataStore:GetOrderedDataStore("wins")

Events:Get("GuideRoundWon"):Connect(function(player)
	wins:IncrementAsync(player.UserId, 1)
end)

local function topTen()
	local result = wins:GetSortedAsync(false, 10):Wait()   -- highest first
	if not result.ok then
		warn(result.error)
		return nil
	end
	local names = {}
	for _, player in Players:GetPlayers() do
		names[player.UserId] = player.Name
	end
	local rows = {}
	for i, entry in result.entries do
		rows[i] = { name = names[entry.key] or "Someone", wins = entry.value }
	end
	return rows
end

while true do
	local rows = topTen()
	if rows then
		State:Set("guide.leaderboard", rows)
	end
	task.wait(30)   -- stay well inside 300 DataStore requests a minute
end
Scripts/Client/GuideLeaderboardHud.luau
local frame = UI:Create("frame")
local lines = {}
for i = 1, 10 do
	lines[i] = UI:Create("text")
	lines[i]:SetParent(frame)
end

State:Observe("guide.leaderboard", function(rows)
	rows = rows or {}
	for i = 1, 10 do
		local row = rows[i]
		lines[i]:SetText(if row then `{i}. {row.name}: {row.wins}` else "")
	end
end)

For the next 10, pass result.nextCursor back: wins:GetSortedAsync(false, 10, cursor). GetSortedAsync(true, ...) reads lowest first, and ties are ordered by key. A place can fill 32 ordered stores of up to 50,000 keys each.

This switches every lamp in the level on at dusk and off at dawn, and spawns one extra lamp from the script. It needs API 1.7. Tag each point or spot light in your level guide_code_lamp. The server sets LightEnabled, so every player sees the same lamps, including players who join later.

A hinged door that swings open Next release

This builds a door on a hinge that a player can push open, rather than one that tweens by script: place a Physics Constraint Actor between the door's Static Mesh Actor (Simulate Physics on) and nothing (Constraint Actor 2 left empty, so it joins to the world), with every Linear motion Locked, Swing 1 Motion set to Limited (how far the door swings) and Swing 2 and Twist Motion set to Locked. A joint that can turn about more than one axis is left out of the place, and Check this place says why. It needs API 1.30. Tag the door actor guide_code_hingedoor; the script listens for the hinge to break under a hard enough shove and reports it.

Scripts/Server/GuideHingeDoor.luau
local door = World:FindByTag("guide_code_hingedoor")[1]
local hinge = Constraints:FromEntity(door)
	or Constraints:Create({
		Type = "hinge", EntityA = door, AnchorA = Vector3.new(0, -50, 0),
		Axis = Vector3.new(0, 0, 1), Limits = { -90, 0 }, BreakForce = 20000,
	})
hinge.Broken:Connect(function()
	State:Set("guide.hingedoor.broken", true)
end)

A door already built as a Physics Constraint Actor in the level publishes as a Constraint automatically, so Constraints:FromEntity finds its joint; a script only needs Constraints:Create for a door it builds itself at runtime. A place holds at most 200 joints, its own included, and pulling a joint harder than BreakForce newtons breaks it for good.

A haunted room with its own look, for one player

This dims and desaturates the picture for one player only, without touching what anyone else sees: tag the trigger volume in your level guide_code_hauntedroom. It needs API 1.29. A client script applies the look a server script sends it over a Remote, so only the player in the room sees it.

Scripts/Server/GuideHauntedRoom.luau
local look = Net:Remote("GuideLook")
World:OnTagged("guide_code_hauntedroom", function(zone)
	zone.Touched:Connect(function(player)
		look:FireClient(player, { Saturation = 0, Vignette = 0.6, ColorGrading = "Noir" })
	end)
	zone.TouchEnded:Connect(function(player)
		look:FireClient(player, false)
	end)
end)
Scripts/Client/GuideLook.luau
local look = Net:Remote("GuideLook")
look.OnClientEvent:Connect(function(t)
	if t then
		Environment:SetLocalLook(t)
	else
		Environment:ClearLocalLook()
	end
end)

What the look sets wins over the server's own values; what it leaves out, such as Bloom, keeps following the server. The look goes when the client script that set it stops, so a bad table sent from the server only fails on that one player's client.
