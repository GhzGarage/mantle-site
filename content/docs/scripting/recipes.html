Copy-ready recipes

Each code block is one file, and the label above it shows where the file goes. The main recipes fit together into one place written in Luau, JavaScript and TypeScript. If a recipe imports the shared configuration module, copy that module too. The language switch only changes the standalone versions, which come in every language.

Each recipe finds the actors in your level by a tag that starts with guide_code_. Give your actors matching tags, or change the tags in the code. The visual scripting examples use their own tags so both can live in one place.

Shared configuration module

This module holds the settings the other recipes share. Copy it into the same nested folders, keeping the exact capitalization of every folder and file name. By default, coins respawn after five seconds and a round lasts 60 seconds. Anything in a Modules folder is only ever used as a module, never run as a script by itself.

Scripts/Shared/Modules/Config/GuideConfig.luau
-- Shared configuration is module-only, including nested Modules directories.
return {
	SafeSpawn = Vector3.new(0, 0, 120),
	CoinRespawnSeconds = 5,
	RoundSeconds = 60,
}

A kill brick that returns the player to safety

This builds a hazard that sends players back to safety when they touch it: tag the hazard actor in your level guide_code_killbrick. The script teleports the player to their saved checkpoint, or to the configured safe spawn if they haven't reached a checkpoint yet.

Scripts/Server/GuideKillBricks.luau
local Config = require("Shared/Modules/Config/GuideConfig")
World:OnTagged("guide_code_killbrick", function(brick)
	brick.Touched:Connect(function(player)
		local spawn = State:Get(`guide.respawn:{player.UserId}`) or Config.SafeSpawn
		player:Teleport(spawn)
	end)
end)

Coins that bob, score and respawn

This builds coins that bob up and down and give a point when collected: tag each coin actor in your level guide_code_coin and set it to Movable. On any other actor the tween raises the error can't tween Position, Rotation or Scale on an entity that isn't dynamic; mark it "dynamic": true in the place (see Errors and limits). The server bobs the coin 40 cm up and down with a tween. When a player touches it, the server hides it, awards one point and shows it again after five seconds. Checking Visible first stops a touch from scoring the pickup again while it's hidden: a hidden entity still collides and still fires Touched. Each bobbing coin uses one of the 256 tweens a place can run at once. Keep these long-lived coins separate from templates you clone and throw away. The tween uses Sine easing with InOut, so the coin slows down gently at the top and bottom of each bob.

Scripts/Server/Modules/Recipes/ScoreRules.luau
local Rules = {}
function Rules.key(player)
	return `guide.score:{player.UserId}`
end
function Rules.award(player)
	local key = Rules.key(player)
	local value = (State:Get(key) or 0) + 1
	State:Set(key, value)
	return value
end
return Rules
Scripts/Server/GuideCoins.luau
local Config = require("Shared/Modules/Config/GuideConfig")
local Score = require("./Modules/Recipes/ScoreRules")
World:OnTagged("guide_code_coin", function(coin)
	local home = coin.Position
	task.spawn(function()
		while true do
			coin:Tween({ Position = home + Vector3.new(0, 0, 40) }, 1, "Sine", "InOut"):Wait()
			coin:Tween({ Position = home }, 1, "Sine", "InOut"):Wait()
		end
	end)
	coin.Touched:Connect(function(player)
		if not coin.Visible then return end
		coin.Visible = false
		Score.award(player)
		task.wait(Config.CoinRespawnSeconds)
		coin.Visible = true
	end)
end)

Scripts/Server/Coins.py
def setup(coin):
    home = coin.position

    def bob():
        while True:
            yield coin.tween({"position": home + Vector3(0, 0, 40)}, 1, "Sine", "InOut").wait()
            yield coin.tween({"position": home}, 1, "Sine", "InOut").wait()
    task.spawn(bob)

    def on_touch(player):
        if not coin.visible:
            return
        coin.visible = False
        key = f"score:{player.user_id}"
        State.set(key, (State.get(key) or 0) + 1)
        yield task.wait(5)
        coin.visible = True
    coin.touched.connect(on_touch)

World.on_tagged("guide_code_coin", setup)

A door that opens when someone walks up

This builds a door that slides open when a player comes close: tag the door actor in your level guide_code_door and set it to Movable, or moving it raises an error (see Errors and limits). Every 0.2 seconds, the script checks whether any player is within 450 cm of the door's saved closed position. If so, the door tweens 390 cm downward over 0.6 seconds. It closes again once everyone has left. The trigger area stays at the door's original position and doesn't move with the door.

Scripts/Server/GuideDoor.luau
local door = World:FindByTag("guide_code_door")[1]
local closed = door.Position
local isOpen = false
while true do
	local near = false
	for _, player in Players:GetPlayers() do
		if player.Position and (player.Position - closed).Magnitude < 450 then
			near = true
		end
	end
	if near ~= isOpen then
		isOpen = near
		State:Set("guide.door.open", isOpen)
		door:Tween({ Position = if isOpen then closed - Vector3.new(0, 0, 390) else closed }, 0.6)
	end
	task.wait(0.2)
end

Round timer on every client HUD

This builds a round timer that shows the current round and time left on every player's screen. You don't need to tag anything in the level: just add both scripts. The server keeps track of the round and the time left. The JavaScript client creates its UI nodes first and then observes State, so players who join late still get the current values. The round-start announcement is a toast: it shows at the top center of each player’s screen for three seconds, then goes away.

Scripts/Server/GuideRounds.luau
local Config = require("Shared/Modules/Config/GuideConfig")
local announce = Net:Remote("GuideAnnounce")
local round = 0
while true do
	round += 1
	State:Set("guide.round", round)
	announce:FireAllClients(`Round {round} started`)
	for remaining = Config.RoundSeconds, 0, -1 do
		State:Set("guide.timeLeft", remaining)
		if remaining > 0 then task.wait(1) end
	end
end
Scripts/Client/GuideHud.js
// Create retained widgets before subscribing. Observe replays current State for late joiners.
const frame = UI.create("frame");
const roundLabel = UI.create("text");
const timeLabel = UI.create("text");
roundLabel.setParent(frame);
timeLabel.setParent(frame);
roundLabel.setSemantics("label", "Current round", "The current round number", 0);
timeLabel.setSemantics("label", "Time remaining", "Seconds left in this round", 0);
State.observe("guide.round", (round) => {
	roundLabel.setText(`Round ${round ?? 0}`);
});
State.observe("guide.timeLeft", (seconds) => {
	timeLabel.setText(`Time left: ${seconds ?? 0}s`);
});
Net.remote("GuideAnnounce").onClientEvent.connect((message) => UI.toast(message, 3));

A button players ask the server to press

This builds a button that squashes down and springs back when a player presses it: tag the button actor in your level guide_code_button and set it to Movable, or scaling it raises an error (see Errors and limits). When the local player touches the button, the client asks the server to press it. The server checks the message and where the sending player really is, and turns away new presses while the button is still busy. It plays both scale tweens, then tells the player the press worked, and a small client script shows that answer as a toast. The client's message never picks which player pressed, and never adds a press by itself.

Scripts/Client/GuideButtonPrompt.luau
local button = World:FindByTag("guide_code_button")[1]
button.Touched:Connect(function(player)
	if player == Players.LocalPlayer then
		Net:Remote("GuidePressButton"):FireServer("press")
	end
end)
Scripts/Server/GuideButton.luau
local button = World:FindByTag("guide_code_button")[1]
local busy = false
local result = Net:Remote("GuideButtonResult")
Net:Remote("GuidePressButton").OnServerEvent:Connect(function(player, message)
	if message ~= "press" then
		result:FireClient(player, "payload")
		return
	end
	if not player.Position or (player.Position - button.Position).Magnitude > 400 then
		result:FireClient(player, "distance")
		return
	end
	if busy then
		result:FireClient(player, "busy")
		return
	end
	busy = true
	local size = button.Scale
	button:Tween({ Scale = Vector3.new(size.X, size.Y, size.Z * 0.3) }, 0.15):Wait()
	button:Tween({ Scale = size }, 0.4, "Back", "Out"):Wait()
	State:Set("guide.button.presses", (State:Get("guide.button.presses") or 0) + 1)
	busy = false
	result:FireClient(player, "pressed")
end)
State:Set("guide.button.presses", 0)
Scripts/Client/GuideButtonResult.luau
Net:Remote("GuideButtonResult").OnClientEvent:Connect(function(result)
	UI:Toast(result == "pressed" and "Button pressed" or `Not pressed: {result}`)
end)

Cloning and destroying things

This shows how to copy and remove objects from a script: place a separate template actor tagged guide_code_template, and another actor tagged guide_code_retired. The script hides the template and makes one visible clone that stays. It then makes a second clone and destroys it, and destroys the retired actor you placed in the level. Players who join later see the clone that stayed and none of the destroyed objects. Clones copy their template's tags, so don't put pickup tags on a template unless you want every clone to be picked up by that recipe too. An NPC can't be cloned: Clone raises the error an NPC can't be cloned; make another with NPCs:Spawn.

local template = World:FindByTag("guide_code_template")[1]
template.Visible = false
local survivor = template:Clone()
survivor.Position = Vector3.new(4500, 2000, 120)
survivor.Visible = true
survivor:AddTag("guide_code_survivor")
local doomed = template:Clone()
doomed:AddTag("guide_code_destroyed")
doomed:Destroy()
local retired = World:FindByTag("guide_code_retired")[1]
retired:Destroy()

This builds checkpoints in TypeScript that work with the Luau kill brick: tag each checkpoint pad in your level guide_code_checkpoint. The TypeScript script imports its nested Rules module. When a player touches a pad, it saves a respawn position (a Vector3) in State. GuideKillBricks.luau, shown above, reads that position the next time the player touches a hazard. Saving data across sessions

Use DataStore Server to save boolean, number or string values so they’re still there in later sessions (tables too, from API 1.13: see saved tables). You can save them for the whole place (Get/Set) or for each player (GetForPlayer/SetForPlayer). There’s nothing to set up in the level.

A missing value doesn’t mean zero

When DataStore:GetForPlayer returns nil, you can’t tell whether this is the player’s first visit, their data hasn’t finished loading, or the load failed. Scripts can’t yet get a signal when data has loaded, or confirmation that a write was saved. Don’t turn nil into zero and write it back, or you could overwrite a larger saved value such as a best score.

Saved tables, removing and listing keys

From API 1.13, DataStore:Set and SetForPlayer also take a table of booleans, numbers, strings and tables, nested up to 4 levels deep and at most 64 KiB, so one key can hold a player's whole profile. Lists come back as lists and objects as objects, but an object's key order isn't kept. Vector3, entities and functions can't be saved. RemoveKey deletes a key, and ListKeys pages through keys that start with a prefix, 100 at a time. ListKeys lists the place’s keys; ListKeysForPlayer(player, prefix, cursor) lists one player’s. SetForPlayer is an error if the player’s account id isn’t ready yet, so call it after they’ve been in the session a moment, as the touch pad does here (tag a pad guide_code_profilepad). Like Get, ListKeys can lag behind other servers: it may not see what another server of the place wrote a moment ago.

Scripts/Server/GuideProfile.luau
World:OnTagged("guide_code_profilepad", function(pad)
	pad.Touched:Connect(function(player)
		DataStore:SetForPlayer(player, "guide.profile", { coins = 120, owned = { "sword", "shield" } })
	end)
end)

DataStore:RemoveKey("guide.event.spring")   -- Get reads nil at once; deleted in the background

local cursor = nil
repeat
	local page = DataStore:ListKeys("guide.", cursor)   -- the place's own keys, up to 100, in key order
	for _, key in page.keys do
		print(key)
	end
	cursor = page.nextCursor
until cursor == nil

A leaderboard across every server

The easy way (API 1.26). Fill an ordered store keyed by player.UserId, then show it with the built-in panel players open with Tab:

Scripts/Server/GuideWins.luau
local wins = DataStore:GetOrderedDataStore("wins")
Leaderboard:Configure("wins", { title = "Most wins", valueLabel = "Wins" })

local function onRoundWon(player)
	wins:IncrementAsync(player.UserId, 1)
end

Use ascending = true in the options table for "lowest is best" (race times), and Leaderboard:Clear() to hide the panel. Keys that aren't a UserId show as written (team names). Server scripts only.

Your own leaderboard UI. This keeps a wins leaderboard for your place and shows the top 10 on every player's screen with your own widgets, for when you want more than the built-in panel. It needs API 1.13. An ordered store keeps one whole number per key and reads them back sorted, across every server of the place. Key it by player.UserId exactly, so each player has one row: that's also how Mantle removes a player's rows when they delete their account, and includes them in their data export. Every ordered-store call returns a Signal that fires once with a result table: ok, error when it failed, and the answer (value, or entries and nextCursor for a page). Call :Wait() on it right away, or connect with :Once. IncrementAsync adds in a single step, so two servers adding a win at the same moment never lose one.

Fire the GuideRoundWon event with the winning player from whichever script decides a round, for example Events:Get("GuideRoundWon"):Fire(player). Nothing else in these recipes fires it, so the board stays empty until you add that line. The store only holds ids, so the server fills in names for players who are in this session.

Scripts/Server/GuideLeaderboard.luau
local wins = DataStore:GetOrderedDataStore("wins")

Events:Get("GuideRoundWon"):Connect(function(player)
	wins:IncrementAsync(player.UserId, 1)
end)

local function topTen()
	local result = wins:GetSortedAsync(false, 10):Wait()   -- highest first
	if not result.ok then
		warn(result.error)
		return nil
	end
	local names = {}
	for _, player in Players:GetPlayers() do
		names[player.UserId] = player.Name
	end
	local rows = {}
	for i, entry in result.entries do
		rows[i] = { name = names[entry.key] or "Someone", wins = entry.value }
	end
	return rows
end

while true do
	local rows = topTen()
	if rows then
		State:Set("guide.leaderboard", rows)
	end
	task.wait(30)   -- stay well inside 300 DataStore requests a minute
end
Scripts/Client/GuideLeaderboardHud.luau
local frame = UI:Create("frame")
local lines = {}
for i = 1, 10 do
	lines[i] = UI:Create("text")
	lines[i]:SetParent(frame)
end

State:Observe("guide.leaderboard", function(rows)
	rows = rows or {}
	for i = 1, 10 do
		local row = rows[i]
		lines[i]:SetText(if row then `{i}. {row.name}: {row.wins}` else "")
	end
end)

For the next 10, pass result.nextCursor back: wins:GetSortedAsync(false, 10, cursor). GetSortedAsync(true, ...) reads lowest first, and ties are ordered by key. A place can fill 32 ordered stores of up to 50,000 keys each.

A hinged door that swings open

This builds a door on a hinge that a player can push open, rather than one that tweens by script: place a Physics Constraint Actor between the door's Static Mesh Actor (Simulate Physics on) and nothing (Constraint Actor 2 left empty, so it joins to the world), with every Linear motion Locked, Swing 1 Motion set to Limited (how far the door swings, with a range that includes 0) and Swing 2 and Twist Motion set to Locked. Turn on Linear Breakable or Angular Breakable and set its threshold, or the joint never breaks and Broken never fires. Set Constraint Actor 1 to the door, leave Component Name empty and turn the linear and angular drives off, or the joint is left out of the place. A joint that can turn about more than one axis is left out of the place, and Check this place says why. It needs API 1.30. Tag the Physics Constraint Actor (not the door) guide_code_hingedoor; the script listens for the hinge to break under a hard enough shove and reports it.

Scripts/Server/GuideHingeDoor.luau
local pivot = World:FindByTag("guide_code_hingedoor")[1]
local hinge = Constraints:FromEntity(pivot)
hinge.Broken:Connect(function()
	State:Set("guide.hingedoor.broken", true)
end)

A Physics Constraint Actor in the level publishes as a Constraint automatically, and Constraints:FromEntity takes that actor (not the door mesh) and returns its joint; it returns nil for any other entity. A script only needs Constraints:Create for a door it builds itself at runtime, as in the joints example (AnchorA is the hinge's position in the door's own space: (0, -50, 0) is 50 cm along its Y axis from the middle, at the door's edge, since Z is up). A place holds at most 200 joints, its own included, and pulling a joint harder than BreakForce newtons breaks it for good.

A door that opens when a player holds E Next release

This builds a door that a player opens by walking up and holding the key for half a second. It needs API 1.38, which no game release carries yet, so publishing a place that uses it is refused until one does (see API versions). Tag the door actor in your level guide_code_interact_door and set it to Movable, or moving it raises an error (see Errors and limits). The server gives the door a prompt that reads "Open door" and fires Interacted once the hold finishes. The script then slides the door down 390 cm over 0.6 seconds and changes the prompt to "Close door", and the next use closes it.

Scripts/Server/GuideInteractDoor.luau
local OPEN = "Open door"
local CLOSE = "Close door"

local function setPrompt(door, text)
	Interaction:SetOptions(door, {
		{ Key = "Primary", Text = text, HoldSeconds = 0.5 },
	})
end

World:OnTagged("guide_code_interact_door", function(door)
	door:SetAttribute("closedZ", door.Position.Z)
	door:SetAttribute("isOpen", false)
	setPrompt(door, OPEN)
end)

Interaction.Interacted:Connect(function(entity, player, part, action)
	if not entity:HasTag("guide_code_interact_door") then
		return
	end
	local closedZ = entity:GetAttribute("closedZ")
	local opening = not entity:GetAttribute("isOpen")
	entity:SetAttribute("isOpen", opening)
	local z = if opening then closedZ - 390 else closedZ
	entity:Tween({ Position = Vector3.new(entity.Position.X, entity.Position.Y, z) }, 0.6)
	setPrompt(entity, if opening then CLOSE else OPEN)
end)

Only the server's Interacted signal should change the door: the client signals (Selected, Progress and the rest) are for a sound or a glow. To stop players using the door, call Interaction:SetEnabled(door, "Primary", false). Interaction:Remove(door) takes the prompt away completely.

Two teams and timed rounds Next release

This builds two teams that play 90-second rounds with a short break between them. It needs API 1.39, which no game release carries yet, so publishing a place that uses it is refused until one does (see API versions). You don't need to tag anything in the level: just add the script. The server creates the teams with Teams:Create and puts each new player on the smaller one by setting Player.Team (see Player). It counts kills for each team, and Match:StartRound starts a timed round. When the round ends, RoundEnded passes the round number, the winner and a reason: "Ended" when a script called EndRound, "Time" when the clock ran out (the winner is always nil then) or "MatchEnded". Match never picks a winner itself, so the script works it out from the kills. Dead players come back after the Respawn.Delay of 3 seconds. At the end of a round everyone gets a fresh character.

Scripts/Server/GuideTeamRounds.luau
local ROUND_SECONDS = 90
local BREAK_SECONDS = 10

Teams:Create("Red", "#E53935")
Teams:Create("Blue", "#1E88E5")
Respawn.Delay = 3

local kills = { Red = 0, Blue = 0 }

Players:OnPlayer(function(player)
	local red = #Teams:GetPlayers("Red")
	local blue = #Teams:GetPlayers("Blue")
	player.Team = if red <= blue then "Red" else "Blue"
	player.Died:Connect(function(_, killer)
		if killer and killer.Team and killer.Team ~= player.Team then
			kills[killer.Team] += 1
		end
	end)
end)

Match.RoundEnded:Connect(function(round, winner, reason)
	if reason == "Time" and kills.Red ~= kills.Blue then
		winner = if kills.Red > kills.Blue then "Red" else "Blue"
	end
	State:Set("guide.lastWinner", winner or "Draw")
	for _, player in Players:GetPlayers() do
		player:Respawn()
	end
	task.wait(BREAK_SECONDS)
	kills.Red, kills.Blue = 0, 0
	Match:StartRound(ROUND_SECONDS)
end)

Match:StartRound(ROUND_SECONDS)

Only the server runs the teams and the rounds. A client can read Player.Team, Match.State, Match.Round and Match.TimeRemaining for a HUD, but it can't change them. Teammates can't hurt each other unless you set Teams.FriendlyFire = true. Team names aren't case-sensitive, and a place can have up to 16 teams. See Teams and rounds for the overview.

Armor, shield and custom damage Next release

This builds a pad that gives a player armor and a shield, and a pool of acid that hurts them. It needs API 1.39, which no game release carries yet, so publishing a place that uses it is refused until one does (see API versions). Tag the pad guide_code_armorpad and the acid guide_code_acid. Touching the pad sets Armor to 50 (the percent of every hit the character shrugs off), MaxShield to 50 and Shield to 50, and lets the shield refill by 10 a second after 5 seconds without a hit. Touching the acid calls TakeDamage(20, nil, "Acid"). The third argument tags the hit with a damageType: use a built-in such as "Bullet", "Melee" or "Explosion", or any word of your own up to 32 characters. Damage goes through armor first, then the shield, then health. So 20 damage becomes 10 after armor, and the shield takes all 10 while it lasts. Damaged fires on the server with the player, the amount that got through armor, the damageType and the attacker (nil here). It still fires when the shield soaks up the whole hit. Set these on a player who has a character: they read nil while the player is respawning.

Scripts/Server/GuideArmorShield.luau
World:OnTagged("guide_code_armorpad", function(pad)
	pad.Touched:Connect(function(player)
		player.Armor = 50
		player.MaxShield = 50
		player.Shield = 50
		player.ShieldRegenRate = 10
	end)
end)

World:OnTagged("guide_code_acid", function(acid)
	acid.Touched:Connect(function(player)
		player:TakeDamage(20, nil, "Acid")
	end)
end)

Players:OnPlayer(function(player)
	player.Damaged:Connect(function(_, amount, damageType, attacker)
		print(`{player.Name} took {amount} {damageType} damage: shield {player.Shield}, health {player.Health}`)
	end)
end)

TakeDamage returns false when nothing got through: the player has no character, is already dead, friendly fire blocked a teammate's hit, or Armor is 100. Armor and the shield settings last for the rest of the session, through respawns, and every respawn starts with the shield full. A killing hit fires Damaged first and then Died, and Died gets the same damageType (see Player).

Sprint with stamina Next release

This builds a sprint that tires the player out, with a stamina readout on their screen. It needs API 1.40, which no game release carries yet, so publishing a place that uses it is refused until one does (see API versions). Tag a pad guide_code_staminapad. Touching it turns StaminaEnabled on for that player. It's off for everyone until a script does that, and turning it on starts the pool full. Sprinting then uses 30 stamina a second, and stamina comes back at 10 a second after 1 second of rest. A sprint stops at zero and can't start again until a tenth of MaxStamina (100 by default) has come back. SprintSpeed is 900 cm/s here. StaminaChanged passes the player, the old value and the new one, in steps of about half a percent of MaxStamina. A nameplate over each player Next release

This puts a name over every other player's head, on your screen only. It needs API 1.41, which no game release carries yet, so publishing a place that uses it is refused until one does (see API versions). It's a client script, and there's nothing to tag. The script makes a text node for each player and calls UiNode:AttachToWorld on it. Bone = "head" puts the plate on the head, Offset lifts it 30 cm, MaxDistance hides it past 2,500 cm, FadeDistance fades it out over the last 500 cm and HideForSelf keeps it off your own character. A plate follows its player and hides while they have no character. A script can float up to 32 nodes at once, and AttachToWorld returns false past that. The script destroys the plate then, and again when the player leaves, so it never wastes the node budget (256 nodes per script).

Scripts/Client/GuideNameplates.luau
local plates = {}

Players:OnPlayer(function(player)
	local plate = UI:Create("text")
	if not plate then
		return
	end
	plate:SetText(player.Name)
	local attached = plate:AttachToWorld(player, {
		Bone = "head",
		Offset = Vector3.new(0, 0, 30),
		MaxDistance = 2500,
		FadeDistance = 500,
		HideForSelf = true,
	})
	if attached then
		plates[player.UserId] = plate
	else
		plate:Destroy()
	end
end)

Players.PlayerRemoving:Connect(function(player)
	local plate = plates[player.UserId]
	if plate then
		plate:Destroy()
		plates[player.UserId] = nil
	end
end)

A plate is only drawn: it can't be clicked. For a marker that stays on the edge of the screen when its target is out of view, pass OffScreen = "Clamp". To stop floating a node without destroying it, call DetachFromWorld. Every option is listed under UiNode.
