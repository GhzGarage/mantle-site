Server, client, shared

The server owns the game: it moves things for everyone, keeps score and decides who wins. A client script runs on one player's machine and handles what that player sees: HUD, toasts, local effects.

Every part of the API exists on both sides, so types and autocomplete are the same everywhere. But some members only work on one side. If you call one on the wrong side, you get a clear error:

UI:Toast can only be called from the client.

Server changes reach everyone

  • Setting Position, Visible and similar, tweens, attributes, tags, clones and destroys are all synced from the server to every player, including players who join later. (This is called replication.)
  • State:Set, teleporting and kicking players.
  • Firing remotes to one player or all of them.

Client changes are local

  • Setting a property of an entity (the object your script uses to work with an actor in the world) on a client changes only that player's view, as on Roblox. When the server next changes it, the server's value wins.
  • HUD text and toasts. Use Players.LocalPlayer to get the local player when it's available.
  • Asking the server for things with Remote:FireServer.

For quick local checks, a standalone client (a separate program, not the editor) can run both sides in one world. In a dedicated session, server scripts run on the server and client scripts run on each player's machine as they join. Test multiplayer behaviour in these separate programs, and include a player who joins late. Scripts don't run in the editor's Play (PIE) mode.

Tags connect scripts to things

Give actors a tag in the editor, then write one script for every actor with that tag. These examples use the tag guide_code_killbrick. The script covers every tagged actor already placed and any added later, clones included. You never need to attach a script to an actor.

Scripts/Server/KillBricks.luau
World:OnTagged("guide_code_killbrick", function(brick)
	brick.Touched:Connect(function(player)
		player:Teleport(Vector3.new(0, 0, 150))
	end)
end)
Scripts/Server/KillBricks.ts
World.onTagged("guide_code_killbrick", (brick: Entity) => {
	brick.touched.connect((player: Player) => {
		player.teleport(new Vector3(0, 0, 150));
	});
});
Scripts/Server/KillBricks.js
World.onTagged("guide_code_killbrick", (brick) => {
	brick.touched.connect((player) => {
		player.teleport(new Vector3(0, 0, 150));
	});
});
Scripts/Server/KillBricks.py
def setup(brick):
    def on_touch(player):
        player.teleport(Vector3(0, 0, 150))
    brick.touched.connect(on_touch)

World.on_tagged("guide_code_killbrick", setup)

Other ways to find things: World:FindByTag(tag) returns a list, and World:FindFirst(name) finds by the actor's name in the Outliner. The same actor always gives you the same object, so you can use entities and players as table keys.

Signals: reacting to things

When something happens in the game, it fires a signal, such as Touched, PlayerAdded, State.Changed or a remote's event. Connect a function to a signal to react to it. Each call runs on its own, so a handler can wait without holding up anything else.

MemberWhat it does
Connect(fn) → ConnectionCall fn every time it fires.
Once(fn) → ConnectionCall fn the next time only.
Wait()Pause until it fires, then return its arguments. In JavaScript it returns a Promise. In Python, save token = signal.wait(), yield that token, then read token.result.
Connection:Disconnect()Stop listening. Everything a script connected is disconnected automatically when the script stops or reloads.
Fire(...)Only for your own events from Events:Get(name). Built-in signals can't be faked.

Waiting and timers

Every language can pause without freezing the game. Each one uses the style its programmers already know:

Luau · like Roblox
task.wait(2)                        -- pause this thread 2 s
task.spawn(function() ... end)      -- run now, in parallel
task.delay(5, function() ... end)   -- run in 5 s
local thread = task.delay(9, boom)
task.cancel(thread)                 -- never mind
TypeScript · async/await
await task.wait(2);                  // inside an async function
task.spawn(async () => { ... });
const id = task.delay(5, () => { ... });
task.cancel(id);
setTimeout(() => { ... }, 500);       // web-style timers work too
JavaScript · async/await
await task.wait(2);                  // inside an async function
task.spawn(async () => { ... });
const id = task.delay(5, () => { ... });
task.cancel(id);
setTimeout(() => { ... }, 500);       // web-style timers work too
Python · generators (like Unity coroutines)
def countdown():
    for n in range(3, 0, -1):
        print(n)
        yield task.wait(1)        # a function that yields can wait
    print("go!")

task.spawn(countdown)             # start it
task.delay(5, lambda: print("5 s later"))

def wait_for_join():
    token = Players.player_added.wait()
    yield token                   # waits for the signal
    player = token.result[0]      # what it fired with
Long loops must wait

Each script gets a CPU budget of 8 ms per second and a memory budget of 16 MiB. If a script goes over its CPU or memory budget, or hits a host limit, Mantle stops that script, along with its tasks and connections. Split long work into chunks with waits in between.

In Python, an operation that would take a script over 16 MiB is refused, and the script is stopped.

Values

Pass ordinary values of your language: numbers, strings, booleans, lists, tables/objects/dicts, Vector3, entities and players. They go into State, attributes and remotes as they are, and come back the same way. Functions can't be stored or sent.

State:Set("round", { number = 3, leader = "ana", spawn = Vector3.new(0, 0, 200) })
local round = State:Get("round")
print(round.number, round.spawn.Z)          -- 3  200
State.set("round", { number: 3, leader: "ana", spawn: new Vector3(0, 0, 200) });
const round = State.get("round");
console.log(round.number, round.spawn.z);    // 3 200
State.set("round", { number: 3, leader: "ana", spawn: new Vector3(0, 0, 200) });
const round = State.get("round");
console.log(round.number, round.spawn.z);    // 3 200
State.set("round", {"number": 3, "leader": "ana", "spawn": Vector3(0, 0, 200)})
r = State.get("round")
print(r["number"], r["spawn"].z)             # 3 200

Positions are in centimetres (100 = 1 m), like Unreal. Rotations are Vector3(pitch, yaw, roll) in degrees.

Sharing code

Put reusable code in Shared/ (both sides) or a Modules/ folder (that side only), then load it from your scripts. The @Shared path shortcut also works in Luau and TypeScript code editors.

Scripts/Shared/Modules/Examples/Config.luau
return { RoundSeconds = 60, SpawnPoint = Vector3.new(0, 0, 150) }
Scripts/Server/ReadConfig.luau
local Config = require("@Shared/Modules/Examples/Config")
Scripts/Shared/Modules/Examples/Config.ts
export const roundSeconds = 60;
Scripts/Server/ReadConfig.ts
import { roundSeconds } from "@Shared/Modules/Examples/Config";
console.log(roundSeconds);
Scripts/Shared/Modules/Examples/Config.js
export const roundSeconds = 60;
Scripts/Server/ReadConfig.js
import { roundSeconds } from "@Shared/Modules/Examples/Config";
Scripts/Shared/Modules/Examples/Config.py
ROUND_SECONDS = 60
Scripts/Server/ReadConfig.py
Config = require("@Shared/Modules/Examples/Config")   # the module itself, loaded once
print(Config.ROUND_SECONDS)

Each labelled block is a separate file. Type Shared/Modules/Examples/Config exactly as shown: paths must match capital letters exactly, on Windows as well as Linux.

  • A Modules folder nested inside another folder still only holds modules.
  • If the capitalisation is wrong, or you require an entry script (a script that runs on its own rather than a module), you get a clear error. A path outside Scripts isn't found.
  • Luau and Python modules must finish loading without waiting.
  • Circular requires (modules that require each other in a loop) are an error.
  • Dynamic import() is blocked in JavaScript and TypeScript.
  • Editing a module restarts all scripts rather than hot-reloading just one.
  • A module is loaded once and reused. In Luau and Python it's shared by the scripts on a side; in JS/TS each script gets its own copy.
  • Python uses require(...) rather than import for your own files: it returns the module object, so Config.ROUND_SECONDS works as usual. Python's own built-in modules (like math) still use import.
  • Client scripts can't load server code; it never leaves the server. Server scripts can't load client code.
  • Luau and Python can only load files in their own language; JavaScript and TypeScript can import each other. Give modules unique names across languages, since an extensionless path can match a file in another language. To share between languages, use State, Events or a Remote (see Mixing languages).

Talking over the network

State is for shared facts such as the score, round or phase. The server sets them. Every script can read them and be told when they change.

Scripts/Server/NetworkState.luau
State:Set("guide.example.timeLeft", 30)
Scripts/Client/NetworkHud.luau
local label = UI:Create("text")
State:Observe("guide.example.timeLeft", function(seconds)
	label:SetText(`Time left: {seconds}s`)
end)
Scripts/Server/NetworkState.ts
State.set("guide.example.timeLeft", 30);
Scripts/Client/NetworkHud.ts
const label = UI.create("text");
State.observe("guide.example.timeLeft", (seconds: number) => {
	label.setText(`Time left: ${seconds}s`);
});
Scripts/Server/NetworkState.js
State.set("guide.example.timeLeft", 30);
Scripts/Client/NetworkHud.js
const label = UI.create("text");
State.observe("guide.example.timeLeft", (seconds) => {
	label.setText(`Time left: ${seconds}s`);
});
Scripts/Server/NetworkState.py
State.set("guide.example.timeLeft", 30)
Scripts/Client/NetworkHud.py
label = UI.create("text")
State.observe("guide.example.timeLeft", lambda s: label.set_text(f"Time left: {s}s"))

Remotes are for one-off messages. A remote is a named channel with FireServer (client to server), and FireClient / FireAllClients (server to clients). On the server, the handler's first argument is the player who actually sent the message.

A few messages sent before a handler connects are held for it (see Errors and limits). But a remote doesn't store anything, and it doesn't replay earlier messages to players who join late. Put things like the current score, round and door status in State instead.

Never trust a client

A client can send anything. When a message says “I pressed the button”, check on the server that the player really is near the button, as in the button recipe.

Mixing languages

Scripts in different languages share one world. They talk through the same three channels, which work the same way in every language:

  • State (with the Changed signal) for shared values.
  • Events: Events:Get("GoalScored") is a named signal for scripts on the same side. Any script can Fire it or connect to it.
  • Remotes between server and clients.

The checkpoint recipe pairs Server/GuideCheckpoint.ts with Server/GuideKillBricks.luau: TypeScript writes a checkpoint vector into State; Luau reads it when the player touches a kill brick. Neither language imports the other's module.

The sections below cover services added in script API 1.4 to 1.30. They're in the Mantle plugin now, so Check All and the type files know them, but publishing refuses a place whose scripts use them until the game release that carries them is out (see API versions). Each section names the version it needs. The examples are in Luau; the other languages use the same members with their own spelling. Every member is listed in the full reference.

Assets your scripts use

A script can only spawn a mesh, show a material or play a sound that was published with the place. Anything placed in the level is published automatically. For an asset nothing in the level uses, such as a projectile a script spawns or a sound it plays on an event, add it to Script Assets:

  1. Choose Tools → Mantle → Place settings. This selects the level's Mantle Place Settings actor, and adds one if the level has none.
  2. In the Details panel, under Mantle → Scripts, add entries to Script Assets and pick each asset. It takes static meshes, materials and sound waves.
  3. Publish. Script Assets are checked and uploaded exactly like placed content, with the same limits.
  4. Find each asset's id in the publish log, one line per asset: Script asset /Game/Props/SM_Boulder.SM_Boulder = ast_u…. The same ids show in the read-only Script Asset Ids list until you close the editor. Use that id in your script.

A mesh brings its slot materials with it. An asset that's also placed in the level, or listed twice, is published once. Check this place names anything the list can't publish, such as a texture, a Sound Cue or MetaSound, or a deleted asset, and Publish refuses the same entries.

Lights (API 1.7)

Every point, spot and directional light in the place is an Entity with LightEnabled, LightColor ("#RRGGBB"), LightIntensity, LightRange and, for spot lights, LightInnerCone/LightOuterCone. LightKind says which kind it is, or nil for anything that isn't a light. Set them on the server and every player sees the change, including players who join later; set them on a client and only that player does. Lights:Spawn Server adds a new light. Shadows are off unless you pass CastShadow = true. A place can have at most 64 spawned lights at once; lights you placed in the editor don't count.

Scripts/Server/Lamp.luau
local lamp = Lights:Spawn("Point", Vector3.new(0, 0, 300), {
	Color = "#FFD9A0", Intensity = 40, Range = 1200,
})
lamp:AddTag("streetlamp")
lamp:Tween({ LightIntensity = 0 }, 5)   -- fade it out over five seconds (API 1.8)

Spawning and recolouring meshes (API 1.8)

Assets:Spawn(assetId, position, props?) Server places one of the place's meshes (placed in the level or listed under Script Assets) and returns it as an Entity. Spawned meshes count towards the same 512 limit as clones. Any mesh can be tinted with Color, faded with Transparency (0 solid to 1 invisible), or given another of the place's materials with SetMaterial(assetId, slot?). Only materials uploaded with the place can be tinted or made see-through.

Scripts/Server/Crates.luau
local CRATE = "ast_u…"   -- the id from the publish log

local crate = Assets:Spawn(CRATE, Vector3.new(200, 0, 100), {
	Scale = 1.5, Color = "#C0392B", Collision = "Blocking",
})
task.wait(3)
crate:Tween({ Color = "#FFFFFF" }, 1)   -- fade the tint away
crate.Transparency = 0.5

Physics objects (API 1.15)

A static mesh with Simulate Physics turned on in the editor is published as a physics object: the server simulates it and every player sees it move. On the server, ApplyImpulse and ApplyAngularImpulse push and spin it, Velocity reads or replaces its speed in cm/s, Anchored = true pins it in place and false lets it fall, and Mass reads its mass in kg. Collided(other) fires on the server when it starts touching something: another entity, a player's character, or nil. Every other entity is always anchored, and physics objects can't be cloned yet. A place can hold 500 physics objects.

Scripts/Server/Crate.luau
local crate = World:FindFirst("PhysicsCrate")
crate.Collided:Connect(function(other)
	print("hit", other and other.Name or "the world")
end)
-- Launch it upwards: an impulse in kg·cm/s, so divide by Mass for the speed change.
crate:ApplyImpulse(Vector3.new(0, 0, 800) * crate.Mass)

From API 1.25, AngularVelocity reads or (server only) replaces a physics object's spin, in degrees per second about the world axes. From API 1.28, PhysicsMaterial reads its surface preset ("default", "rubber", "ice", "metal", "wood" or "stone"), and a server script can change it, anchored or not; every player sees the new surface on its next bounce or slide. Setting either on an Anchored object, or one with no physics block, is an error.

Scripts/Server/IcyWheel.luau
local wheel = World:FindFirst("Wheel")
wheel.Anchored = false
wheel.PhysicsMaterial = "ice"          -- API 1.28: slides instead of gripping
wheel.AngularVelocity = Vector3.new(0, 0, 180)  -- API 1.25: half a turn a second about world Z

Joints: welds, hinges and ropes (API 1.30)

A Physics Constraint Actor between two physics objects (or one and the world) publishes as a Constraint: a weld (no movement between them), a hinge (one turns about an axis, within limits) or a rope (the anchors stay within a length of each other). Constraints:Create(params) Server makes one at runtime and returns it; Constraints:FromEntity(entity) finds the joint a place's own Constraint made. Pull a joint harder than its BreakForce (newtons) and it breaks for good: Broken fires once, on the server. The two joined entities stop colliding with each other, and a place holds at most 200 joints, its own included. Nothing of the joint replicates: clients just see the entities move.

Scripts/Server/Door.luau
local door = World:FindFirst("Door")
local hinge = Constraints:Create({
	Type = "hinge", EntityA = door, AnchorA = Vector3.new(0, -50, 0),
	Axis = Vector3.new(0, 0, 1), Limits = { -90, 0 }, BreakForce = 20000,
})
hinge.Broken:Connect(function() print("the door came off") end)

Raycasts and area queries (API 1.6)

World:Raycast(origin, direction, params?) returns the first thing a ray hits as a table of Entity, Player (set when it hit a character), Position, Normal and Distance, or nil. Spherecast and Blockcast sweep a ball or box the same way, and GetEntitiesInRadius and GetEntitiesInBox list everything inside a shape, nearest first. params takes MaxDistance, Include, Exclude, Tag and IgnorePlayers. Queries run on the machine that asks, work on both sides, and reach at most 1 km.

Scripts/Server/Laser.luau
local laser = World:FindFirst("Laser")
while true do
	local hit = World:Raycast(laser.Position, Vector3.new(1, 0, 0), { MaxDistance = 3000, Exclude = { laser } })
	if hit and hit.Player then
		hit.Player:TakeDamage(10)   -- API 1.9
	end
	task.wait(0.25)
end

Health and damage (API 1.9)

Each player's character has Health and MaxHealth (100 unless a script changes it), plus WalkSpeed (500 cm/s) and JumpHeight (about 90 cm). Read them anywhere; set them on the server. TakeDamage(amount, source?) goes through the same path weapons use, and source is the player credited with a kill. Heal, Kill and Respawn(position?) return false when they can't apply, for example while the player is dead or driving. Died(player, killer) and HealthChanged(player, old, new) fire on the server and on every client.

Scripts/Server/Health.luau
Players:OnPlayer(function(player)
	player.Died:Connect(function(_, killer)
		if killer then
			print(`{killer.Name} got {player.Name}`)
		end
	end)
end)

World:OnTagged("healpad", function(pad)
	pad.Touched:Connect(function(player)
		player:Heal(25)
	end)
end)

Input and camera (API 1.10)

On a client, Input:BindAction(name, keys, callback) calls you with "Began" when the player presses one of the keys and "Ended" when they let go. Keys are named like "Q", "5", "F4", "MouseMiddle", "ButtonX" or "Tab". Keys Mantle uses for its own controls can't be bound; Input:GetBindableKeys() lists the free ones. Tab also opens the built-in leaderboard panel (API 1.26; see Leaderboard), but it isn't reserved: your script's binding still gets the press. From API 1.22, BindAxis reads the sticks, triggers and mouse wheel; a trigger Mantle uses only as a button (fire, aim) can still be read as an axis, since only the sticks' movement and each trigger's click are reserved. Camera can hold the view in first person (Camera.Mode = "FirstPerson"), cut or tween to a fixed shot (SetFixed, TweenFixed), follow an entity (Follow), change FieldOfView and Shake. Everything goes back to Mantle's own camera when the script stops or the player respawns, or when you call Camera:Reset().

Scripts/Client/Overview.luau
local tower = World:FindFirst("Tower")

Input:BindAction("overview", { "Q" }, function(phase)
	if phase == "Began" then
		Camera:TweenFixed(tower.Position + Vector3.new(-2000, 0, 1500), tower.Position, 1.5, "Sine", "InOut")
	else
		Camera:Reset()
	end
end)

Sounds and music (API 1.12)

Sounds:Play(sound, params?) plays one of the place's uploaded sounds: a sound emitter's SoundId, or a sound's asset id. Give it a Position or AttachTo entity to place it in the world, where it fades out at Radius (4,000 cm by default); without either it plays flat, like an interface sound. From a server script every player hears it, or only params.Player; from a client script only that player does. It returns a SoundHandle with Stop, SetVolume and IsPlaying. Each player has one music track: Sounds:PlayMusic crossfades to a new one and StopMusic ends it. A placed sound emitter is an Entity with PlaySound, StopSound and SoundVolume.

Scripts/Server/Bell.luau
local bell = World:FindFirst("Bell")
local BELL_SOUND = "ast_u…"   -- a sound listed under Script Assets

bell.Touched:Connect(function(player)
	Sounds:Play(BELL_SOUND, { AttachTo = bell, Radius = 3000, Pitch = 0.9 })
end)

Particle effects (API 1.19)

Mantle has five built-in particle effects: Smoke, Fire, Sparks, Dust and Glow. You can't upload your own particle systems. Effects:Play(archetype, position, params?) shows one for Duration seconds (1 by default, at most 10), and params can change its Color, Size, Rate, Speed, Lifetime and Rotation. From a server script every player sees it, but a player who joins later doesn't; from a client script only that player does. A Mantle Effect placed in the level is an Entity with PlayEffect, StopEffect, SetEffectColor and SetEffectRate, and those changes do reach late joiners. The five effect systems ship with the same release; until a build carries them, effects draw nothing.

Scripts/Server/Explosion.luau
local function explode(position)
	Effects:Play("Fire", position, { Size = 120, Rate = 150, Duration = 0.4 })
	Effects:Play("Smoke", position, { Duration = 2 })
end

Time of day and weather (API 1.4 and 1.11)

Every server has one sky, shared by every player. Environment.TimeOfDay runs from 0 to 24 (servers start at 9, and a day lasts 30 real minutes), IsNight is true while the sun is down, and Weather is Clear, PartlyCloudy, Overcast, Rain or Storm. WeatherChanged fires when the weather turns, and LightningStrike Client fires with each flash so you can play your own thunder. From API 1.11, server scripts can change it: set ClockTime or TimeScale, FreezeClock(), hold the weather with SetWeather until ResumeNaturalWeather, and adjust the fog, stars, sun and the picture's colour. PropertyChanged fires everywhere when a script changes one of these.

Scripts/Server/Storm.luau
Environment.ClockTime = 21        -- jump to night
Environment:SetWeather("Storm", 30)  -- blend into a storm over 30 s
task.wait(120)
Environment:ResumeNaturalWeather()

From API 1.27, a server script can also set Bloom (0 to 4, how strongly bright things glow) and a fixed colour-grading look with ColorGrading ("Warm", "Cool", "Noir", "Sepia", "Vivid" or "Faded") and ColorGradingIntensity (0 to 1, how strongly it shows). Creators can't upload their own colour-grading textures yet.

Scripts/Server/Flashback.luau
-- A black-and-white flashback with a strong glow, fading back to colour.
Environment.ColorGrading = "Noir"
Environment.Bloom = 4
task.wait(10)
for i = 10, 0, -1 do
	Environment.ColorGradingIntensity = i / 10
	task.wait(0.2)
end
Environment.ColorGrading = nil
Environment.Bloom = nil

From API 1.29, a client script can give one player their own look on top of the server's, with Environment:SetLocalLook(look) Client. look takes any of ExposureBias, Saturation, Contrast, Vignette, ColorTint, Bloom, ColorGrading and ColorGradingIntensity, each clamped the same way as the server property of the same name. What the look sets wins over the server's value; what it leaves out follows the server, including later server changes. Each call replaces the whole look, nothing replicates, and the look goes when the script that set it stops. Environment:ClearLocalLook() Client gives the server's look back.

Scripts/Client/HauntedWing.luau
-- This player only: grey and vignetted, with a Noir grade the server's own bloom shows through.
Environment:SetLocalLook({ Saturation = 0, Vignette = 0.6, ColorGrading = "Noir" })
task.wait(5)
Environment:ClearLocalLook()

Leaderboard (API 1.26)

Mantle has one built-in leaderboard panel. A server script picks the board with Leaderboard:Configure(store, options?) Server, where store is the name of an ordered store from DataStore:GetOrderedDataStore. Players press Tab (or, on a gamepad, the settings drawer's Leaderboard row) to see its top 10, each row with the player's picture, name and value; options.title and options.valueLabel head the panel and its value column, and options.ascending shows lowest first. The panel re-reads the store every 30 seconds while anyone is playing. Leaderboard:Clear() Server takes the panel down. One board shows at a time; call Configure again to switch.

Scripts/Server/Wins.luau
local wins = DataStore:GetOrderedDataStore("wins")
Leaderboard:Configure("wins", { title = "Most wins", valueLabel = "Wins" })

local function onRoundWon(player)
	wins:IncrementAsync(player.UserId, 1)
end

See the leaderboard recipe for the manual, GetSortedAsync-driven version, useful when you want your own on-screen leaderboard instead of the built-in panel.

Chat (API 1.14)

Chat.MessagePosted(player, text) fires for what players say, with the text already filtered. On the server it fires for every player's line; on a client, for each line that player's chat box shows. Chat:SendSystemMessage(text, player?) Server posts a line from the place, to everyone or to one player. It goes through the same chat filter, is at most 500 characters, and a server can send 10 a minute. It returns false when it can't be sent right now.

Scripts/Server/Commands.luau
Chat.MessagePosted:Connect(function(player, text)
	if text == "!spawn" then
		player:Respawn()
		Chat:SendSystemMessage("Sent you back to the start.", player)
	end
end)

NPCs (API 1.17)

NPCs:Spawn(position, look?, yaw?) Server adds a character that the server walks and animates, and every player sees. look picks the base body (Body = "male" or "female", SkinTone, EyeColor, Height). MoveTo(position) walks it around walls and obstacles, and MoveCompleted(success) fires when the walk ends. PlayClip plays "walk", "idle", "turn_left" or "turn_right". From API 1.23 NPCs have Health, take weapon damage and TakeDamage, fire Died, and can play the place's own animation clips with PlayAssetClip. A place holds at most 50 NPCs at once, and spawning past that is an error. NPCs:FromEntity turns a raycast hit back into its NPC. To play one of the place's own clips on an NPC, use PlayAssetClip rather than passing the clip's id to PlayClip, so the place records the API version it needs.

Scripts/Server/Guard.luau
local a, b = Vector3.new(0, 0, 0), Vector3.new(2000, 0, 0)
local guard = NPCs:Spawn(a, { Body = "female" })

local target = b
guard.MoveCompleted:Connect(function(success)
	target = if target == a then b else a
	task.wait(2)
	guard:MoveTo(target)
end)
guard:MoveTo(target)

Animated meshes (API 1.18)

A Skeletal Mesh Actor set to Use Animation Asset publishes as an animated mesh that plays its clip in step on every screen (see Building a place). PlayClip(clipAssetId?, params?) plays one of the place's animation clips on it, or restarts the one it plays now when you leave the id out. params takes Loop (true by default; false holds the last frame), PlayRate (0 to 10) and StartOffset in seconds. StopClip() returns it to its resting pose, and ClipTime reads how far into the clip it is. From the server every player sees it, late joiners included; from a client only that player does. The clip must be made for the mesh's own skeleton.

Scripts/Server/Windmill.luau
local windmill = World:FindFirst("Windmill")
windmill:PlayClip(nil, { PlayRate = 3 })   -- spin three times as fast
task.wait(10)

Crowds (API 1.16)

A Mantle Crowd Spawner placed in the level fills its lanes with ambient walkers. Crowds:Get(spawner) Server returns its Crowd: set Density (0 to 1 of the count you authored), Enabled, Paused or, from API 1.21, Seed, and every player sees it. From API 1.24, Crowds.PointReached(spawner, point, npc) Client fires when one of the crowd's people arrives at one of the spawner's points of interest. Crowd Spawners themselves can't be published until the next release either.

Scripts/Server/Rush.luau
local crowd = Crowds:Get(World:FindFirst("MarketCrowd"))
crowd.Density = if Environment.IsNight then 0.2 else 1

Vehicles

Vehicles:Spawn("offroad" | "sports", position) Server (API 1.1) works today and returns the car as an Entity. Seat, Eject, GetSpeed and SetPaintColor work with it. Next release Spawn also takes the id of a creator vehicle the place lists, and Vehicles:SetLivery(vehicle, index) (API 1.20) puts on one of that vehicle's liveries, or takes it off with -1.

Scripts/Server/Taxi.luau
Players:OnPlayer(function(player)
	local car = Vehicles:Spawn("sports", Vector3.new(0, 400, 50))
	Vehicles:SetPaintColor(car, "#F4C20D")
end)
