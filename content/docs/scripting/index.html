Scripting is in preview

Luau, TypeScript, JavaScript, Python and visual scripts all work in development builds, and hosted sessions are rolling out. Details on these pages may change before general release.

Five-minute start

  1. Find your level's folder

    Your level lives somewhere under Content/, for example Content/MyPlace/MyPlace.umap. Its scripts go in a folder called Scripts right next to it: Content/MyPlace/Scripts/.

  2. Make a Server folder inside it and add a file
    Scripts/Server/Hello.luau
    print("Hello from the server!")

Players:OnPlayer(function(player)
	print(`{player.Name} joined`)
end)
    Scripts/Server/Hello.ts
    console.log("Hello from the server!");

Players.onPlayer((player: Player) => {
	console.log(`${player.name} joined`);
});
    Scripts/Server/Hello.js
    console.log("Hello from the server!");

Players.onPlayer((player) => {
	console.log(`${player.name} joined`);
});
    Scripts/Server/Hello.py
    print("Hello from the server!")

def on_join(player):
    print(f"{player.name} joined")

Players.on_player(on_join)

    Players:OnPlayer (JavaScript/TypeScript Players.onPlayer, Python Players.on_player) runs your function for every player already in the session, and again for each player who joins later. So the welcome still works if your script starts after someone is already in, including in standalone development. The name it prints is the real player's name.

    If you only want players who join after you connect, use the PlayerAdded signal instead.

  3. Check and publish

    Run Check All in the Scripts panel, then publish with Mantle → Publish. Publishing creates a revision. When players join a session, it uses the published revision.

  4. Join in a separate client

    Start or request a session for your published place, then join it with the Mantle client. Anything a server script prints goes to the server log. Anything a client script prints goes to that client's log. Script messages appear under LogMantleScript and name the file they came from.

    Scripts don't run when you press the editor's Play (PIE) button. Test in a separate Mantle server and client, or in a published session.

  5. Edit, recheck and republish

    Save your changes and publish a new revision. The next session uses it.

    In development builds, you can skip publishing while you work. Start a server or client with -MantlePlace=<path>/place.json and it runs the Scripts/ folder beside that file. It also picks up your changes while it's running (hot reload). An edited script is swapped in place. Adding or removing files, or editing a module, restarts all scripts. Published sessions never hot-reload.

The three rules

RuleExample
1. Scripts are files in the Scripts folder beside the level.Content/Obby/Obby.umap → Content/Obby/Scripts/
2. The folder decides where a script runs.Server/ runs on the server. Client/ runs on each player's machine. Shared/ and any Modules/ folder hold libraries that only run when something requires them.
3. Tags connect scripts to things.Tag actors in the editor (Details → Actor → Tags), then World:OnTagged("killbrick", …).

The file extension picks the language: .luau/.lua, .ts, .js or .py. You can mix languages in one place.

Inside Server/, Client/ and Shared/, organise files however you like (Server/Combat/Guns.luau runs). A few rules apply:

  • Folder names must match exactly, including capital letters. server/ isn't recognised.
  • Files placed directly in Scripts/, or outside Server/, Client/ and Shared/, are skipped with a warning in the log.
  • Script paths can use only letters, digits, _, . and - (no spaces), up to 200 characters.
  • Each file can be up to 1 MiB.
