Build scripts visually

To make a visual script, create a MantleScriptGraph asset in your level’s Scripts/Server or Scripts/Client folder. The folder name must match exactly, including capital letters. Graphs can’t go in Shared/. A graph saved anywhere else won’t compile, and you’ll see a warning that tells you why. Open the asset to edit it in the graph editor.

  • Palette. Add nodes from the palette or its search. Categories are Flow Control, Variables, Custom Events, Functions, Literals, Math, Compare, Boolean, Text (Concat, Format), Vector3 and Utilities (Reroute), plus comments and every scripting API member, grouped by class.
  • Pins. Execution pins set the order things happen in. Data pins carry values. The editor checks the types when you connect pins, and each pin is colour-coded by its type.
  • My Blueprint. Declare graph variables, custom events and functions here. The palette then offers Get/Set nodes for each variable, Fire/On nodes for each event, and Call/Function/Return nodes for each function.

Compiling and errors

When you save a graph, Mantle compiles it. The graph also compiles when you first open it. Results appear in the Compiler Results panel, and nodes with errors get an error badge. Click or double-click a result to jump to its node. A few problems affect the whole graph rather than one node, such as an execution wire left unconnected at one end, so they don’t point at a single node.

Saving also writes a generated file next to the asset. You don’t edit or upload it yourself. When you publish, Mantle compiles the asset again. That way the published script always matches the published graph.

If a graph script hits an error while your game is running, the error names the graph and node (Server/GraphKillBricks.graph, node "<title>" (<id>): …) and shows up in the open graph’s Compiler Results.

Example graphs

These three graphs mirror the kill brick, coin and door code recipes. They use their own tags and names (GuideGraphKillBrick, GuideGraphCoin and an actor named GuideGraphDoor), so you can use them in the same place as the code recipes without both reacting to the same actors.

Each graph is shown as JSON, the text form of what you build in the graph editor. Node kinds such as event, call, branch, while, foreach and delay correspond to palette nodes. The coin and door graphs use the Position Tween Goal node (Vector3 category) to build the goal for Entity.Tween.

KillBricks graph

A server graph saved as Scripts/Server/GraphKillBricks.

GraphKillBricks · graph JSON
{
  "name": "KillBricks",
  "side": "server",
  "nodes": [
    {"id": "tagged", "kind": "event", "member": "World.OnTagged", "inputs": {"tag": "GuideGraphKillBrick"}},
    {"id": "touch", "kind": "event", "member": "Entity.Touched", "target": "@tagged.entity"},
    {"id": "tp", "kind": "call", "member": "Player.Teleport", "target": "@touch.player", "inputs": {"position": {"vector": [0, 0, 150]}}},
    {"id": "log", "kind": "print", "text": "a player hit a killbrick"}
  ],
  "exec": [["tagged", "touch"], ["touch", "tp"], ["tp", "log"]]
}
