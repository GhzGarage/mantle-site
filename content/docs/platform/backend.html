How content is screened

Uploaded images, scripts and avatar items are screened before other players can see them, and moderators review anything that gets flagged.

  • Live Uploaded images and scripts (in every language, including visual scripts) are checked automatically before anyone else can see them. If the check can't finish, the content stays unapproved.
  • Live Meshes, sounds and other assets such as materials, skeletal meshes, animation clips and heightfields have no automatic check. Moderators act on reports about them.
  • Live Avatar items: each item's thumbnail, name and description are checked the same way.
  • Live Library items: a vehicle, weapon or script package's thumbnail, name and description are checked too. If the check keeps failing, a moderator decides.
  • Live Chat filter: chat messages are filtered before anyone sees them. Some words are replaced with asterisks, and some messages aren't sent at all: "That message was not sent because it breaks the chat rules."
  • Live Review: flagged content waits for a moderator to approve or reject it.
  • Live Acting on reports: moderators can review and resolve reports, take content down, shut down community servers and suspend private servers.
  • Live Strikes: a moderator can record a strike against an account when its content is taken down for breaking someone's rights, or by hand. At 3 strikes the account can no longer make avatar items or library items public: "Public publishing is turned off for this account. Publish privately, or contact support." Private publishing still works, and nothing lifts the block automatically.
  • Planned Other penalties for accounts, such as suspensions.
  • Planned Screening for display names and world names.

Uploads and saved data Live

  • A world can't be published while any asset or script it uses is still unapproved. Only approved content can be downloaded by players.
  • Saved data is protected so that two servers can't silently overwrite each other's changes. See Saved data for the limits.

The library: vehicles, weapons and script packages Live

The library holds three kinds of item: vehicle, weapon and script (a script package). The Mantle plugin and the ASSETS tab use these routes for you; this section is for anyone building their own tools.

  • Browsing: GET /library/items?kind=script and GET /library/items/mine?kind=script list script packages, as they do vehicles and weapons. Each card carries price (always 0, free, for now) and, on an item you got, source ("free").
  • Details: GET /library/items/{itemId} also answers storedByMyPlaces: [{id, name}], your own places whose live or staged version stores any version of the item.
  • Versions: a script package's versions carry scripts and manifest and no primaryAssetId. Versions never change once made.
  • Removing from your library: DELETE /library/items/{itemId}/get answers 204, and again 204 if you call it twice while the item is still visible to you (your own item, or one that is active, public and approved; your own item stays yours). Once an item has been delisted, made private or taken down, a repeat call answers 404 not_found. Your places that store the item keep running, and their next publish, promotion or rollback is refused until the entry is removed from storage. Player sign-ins and creator tokens can both use it.

Publishing a script package

POST /library/items with kind: "script", and POST /library/items/{itemId}/versions for a script package, take:

  • scripts: 1 to 64 files, each {path, side, language, source}. The path starts with Server/, Client/ or Shared/, matching side (server, client or shared) exactly; paths are unique ignoring capital letters, up to 200 characters, and can't be a visual-script .graph. language is luau, javascript, typescript or python (a TypeScript file's source is its compiled JavaScript). source is the src_ id of an approved script upload (POST /scripts). You don't have to be the one who uploaded it: identical scripts are stored once and every one is screened, so owning the upload proves nothing.
  • manifest: {name, description, parameters, settings}, the package's package.json, with up to 16 parameters and 16 settings. Each option is {name, type, default, help, required, min, max, options}: type is string, number, boolean or choice; default and help are text, and a default of "" means none; required is always present; min and max (numbers only) and options (choices only, 2 to 32 entries) appear only when set. Names are unique in each list ignoring capital letters.

A script package body can't carry primaryAssetId or dependencyAssetIds, and a vehicle or weapon body can't carry scripts or manifest: both are refused with item_field_not_allowed.

Stored packages and Script Points in a place

  • Storage: a place file's storage lists up to 32 {name, item, version} entries, script packages included. A script package's entry can also carry settings: {key: string}, at most 16 keys, values up to 256 characters. A setting left out takes the manifest's default.
  • Script Points: an entity of type ScriptPoint has storageItem (the name of a storage entry, which must be a script package), parameters (an object of text values, at most 16, keys matching ^[A-Za-z][A-Za-z0-9_]{0,31}$, values up to 256 characters) and enabled (true by default). A place has at most 64.
  • Checked at publish: publishing and previews hold each stored package's settings, and each enabled Script Point's parameters, to the manifest of the version the place pins. A refusal answers 409 with an issues list and a top-level code: storage_unavailable if any issue has it, then the wrong-kind code if any issue has it, and otherwise the first issue's code. Each issue has a path and a plain-words message. Switched-off Script Points aren't checked. Promoting or rolling back to a sealed revision doesn't check them again, since neither the revision nor the versions it pins can change.
  • Resolving storage: a script package's entry answers kind: "script", scripts (every file of the package, all sides; the game keeps only the ones its side runs), manifest and the settings the revision sealed. A package Mantle has taken down answers status: "taken_down", scripts: [], a manifest of null and settings of {}, so it stops running in every place.

Chat and voice Live

Text chat and voice are tied to the session you're playing in.

  • Chat: only players in a running session can read or send its messages, and blocks apply in both directions. You can send 30 messages a minute. Going faster shows "You are sending messages too quickly. Wait a moment and try again."
  • Voice: each session has one voice room, and only players in that session can join it.

Account deletion and data retention

Deleting an account takes effect straight away: your profile and saved progress are removed, your published worlds are taken down and your creator tokens and server keys are revoked. Your published library items and avatar items are delisted, so a place that stores one of your library items has its next publish refused. Items you got are removed, private servers you own are deleted, and assets and scripts you uploaded are kept. The backend has a DELETE /me route that needs a confirm body, but you can't delete your account from inside Mantle yet. See Deleting your account or data for how to ask.

  • Chat messages are deleted after about 90 days.
  • Play history is deleted after about a year.
  • Saved data changes (the audit log of writes and deletes) are kept for about a year.
  • Deleted private servers lose their name, members and invites after 30 days.
  • Revoked or expired creator tokens are deleted 30 days later.
  • Delisted avatar items lose their name, description and thumbnail after 30 days.
  • Resolved reports are deleted a year after they're resolved. Reports nobody reviewed are deleted a year after they were filed.
  • Deleted worlds, including worlds you delete from My Places, are removed for good after 180 days.
  • Old world versions can be rolled back to for 180 days after they stop being live (30 days for previews and staged versions that never went live). After that they're deleted.
